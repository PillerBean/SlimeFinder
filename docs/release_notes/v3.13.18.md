## 界面：搜索页 A/B/C 重排

搜索页左参数列重组为三组，原则是「搜索方式只决定采样/复核策略，结果要求单独成组」：

- **A 搜索方式**：环形显示四档扫描方式（撒点抽取 / 预筛精修 / 环带上界复核 / 暴力遍布）；
  图案/正方形密度显示原「匹配方式」算法与参数。
- **B 结果要求**：搜索范围、图案/密度模式与方案、区域形状、**最低密度 / 忽略阈值改为常显可调**
  （此前藏在「自定义方案」高级项里，默认方案下看不到）；目标数量、达到即停、智能范围并入
  「停止与数量」子组；环形内外半径从设置页迁移到此处（默认 24 / 128）。
- **C 执行设置**：线程 / GPU（含高级项）/ RAM 预算只读摘要 / 缓存管理。
- 新增「按群系权重排序（Java）」开关（默认勾选 = 与旧行为一致；仅 Java + 环形可编辑）。
  取消后以纯方块数排序，Bedrock 始终为纯方块数口径。

## 环形 / k3 预筛

- 新增 `cachePrescanSeeds`：Bedrock 且本地缓存完整覆盖搜索区域时，可直接从缓存位图在 CPU 上
  按行流式统计窗口密度生成预筛种子（确定性、免 GPU 依赖）。
- 集成取舍按实测：生产参数下 GPU 预筛仍更快（8192²：69ms vs 111ms；16384²：190ms vs 662ms），
  因此**有 GPU 时仍走 GPU 预筛；GPU 不可用/失败时自动用缓存预筛兜底**，两路都不可用才回退快速抽样。
  无 GPU 的 Bedrock 用户首次可以在「预筛精修 / 环带上界复核」档拿到完整质量结果。
- 日志新增预筛来源：`[环形] 缓存预筛：…` / `[环形] 预筛来源：缓存位图|GPU（cachePrescanUsed=…）`。
- 对拍：无每带截断配置下 GPU 与缓存种子逐条一致；生产参数下仅「每带 topPerBand 边界 count 平局」
  取舍不同（GPU 该处本身不定，同一输入三次运行种子数 227/226/224，缓存版确定性 227）；
  k3 最终最优候选一致。详见 `docs/planning/k3_cache_prescan.md`。

## 兼容性

- 结果语义、缓存格式与 3.13.17 兼容；旧的 `config.json` 可直接沿用（新增设置项有默认值）。
- 默认 GPU 仍关闭；需要用户勾选。
- 环形内外半径现在在搜索页调整；`config.json` 中 `settings.ringInner/ringOuter` 字段与旧值兼容。

## 已知未完成

- `version.json / version-beta.json` 更新清单自 3.13.8 起未随测试版更新；测试通道提示仍指向 3.13.8
  （本次发布后单独补清单，见仓库 `docs/planning/HANDOFF_2026-11-29.md`）。
- `scripts/qa/audit_corruption.py` 与 `scripts/qa/run_all_tests.ps1` 路径仍停留在 v3.12.0 拆树前，
  当前运行会误报/找不到文件，需要单独修复（不是本次发布门禁）。
- 发现既有缺陷：`CacheManager::lookup` 的 thread_local「上次命中 range」快查在 range 重叠时
  结果依赖访问顺序（与文档语义不一致）；生产缓存不重叠因此不受影响，已记录待修。
- CPU 缓存预筛目前约 2.5 ns/窗口，后续可做 AVX2 位展开提速，再评估改为缓存优先。
