# SlimeFinder v3.13.8

v3.13.8 是正式版，替代 v3.12.3。

> **v3.12.3 已撤回正式版资格。** v3.12.3 的构建缓存存在并发读写与保存数据丢失风险；
> 已在社交平台传播的副本无法收回，请使用 v3.13.8 重新安装并重新构建缓存。
>
> 自 v3.12.3 起程序只提示新版本，不会自动下载或自动安装；请手动下载 Setup.exe，
> 核对 SHA256 后安装。

## 关键修复

### 缓存构建

- 修复构建模式下工作线程无锁遍历缓存范围、与归并线程并发改写导致的偶发崩溃/半写缓存。
- 构建开始前从现有本地缓存包恢复内存缓存，修复重启后续传失效。
- 构建保存改为每 5 段检查点 + 结束/取消时保存，避免每段全量重写造成界面冻结。
- 容量达到上限后立即停止调度新分块，不再继续空扫。
- 搜索/构建运行期间禁止清空、导入、删除缓存包，避免和 worker 竞争。

### GPU

- GPU 图案/密度的计数器、直方图、命中回读失败现在会返回错误并回退 CPU，
  不再把空结果/截断结果当成成功。
- GPU 行带匹配失败后不再对整区重复派发一次 GPU，直接走 CPU 兜底。

### 取消与结果

- “最优候选”和“最小密度为 0”的快速路径取消后不再返回部分结果并标记成功。
- 环形搜索的严格重算段纳入异常保护；关窗时先取消并拒绝销毁，避免 worker 访问已销毁窗口。
- 分带缓存搜索不再被每个 band 覆盖全局扫描分母，修复 N/M 超过 100%。
- 分带搜索聚合 GPU 使用、回退原因、剪枝统计。

### 界面

- 搜索成功/错误现在会进入反馈面板（此前 Success 级被过滤，错误也不进反馈）。
- 修复缓存上限修改不落盘：设置值与 `cache.maxSizeMB` 双向同步。
- 修复参考对拍脚本路径（`tests/reference/verify_against_reference.py`）。

## 兼容性

- 结果语义、缓存格式与 3.13.7 兼容。
- v3.12.3 的本地缓存仍可读取，但建议重新构建以清除可能的不完整缓存。
- 默认 GPU 仍关闭；需要用户勾选。

## 已知未完成

- 分带缓存路径仍不保证 `stopAtTarget` 的全局最近 N 语义（本次未改）。
- 部分 GPU 失败后的扫描仍会从 CPU 全量重扫（未做 tile 断点续扫）。
- 环形搜索仍使用独立等待模型，尚未并入统一搜索状态机。
