## 修复的 bug（本轮）

1. **GPU 流式匹配 OpenCL 参数宽度错误（3.9.8）**：`bool` 按 1 字节传 int 参数、Windows `long` 32 位传 64 位参数 ⇒ `CL_INVALID_ARG_SIZE` ⇒ 静默回退 CPU。修复后：
   * 12000² 密度：43.4 → **7.5 ms**
   * 32768² 密度：166 → **27.4 ms**
2. **严格模式 + 分层/采样算法静默算错（3.9.5）**：引擎把算法强制当密度语义；改为严格模式一律精确。
3. **并行分批导致严格匹配 100 倍回归（3.9.7）**：分批只在早停时启用（性能基线抓到）。
4. **GPU 行带早停结果不确定（3.9.9）**：按 (d2,z,x) 排序入堆 + 安全余量，5 次连续一致。
5. **GPU 命中总数统计错误（3.9.8）**：增加 `outTotal` 回传裁剪前真实值。

## 教训

1. 静默回退是最危险的失败模式：功能测试全绿，但性能白给。**分段计时 + 真机探针 + 性能基线**三者缺一不可。
2. mock GPU 提供者测不出真实驱动的参数校验错误。
3. 性能优化必须带「结果与 CPU 完全一致」的对拍，否则越优化越错（本轮两次遇到）。
