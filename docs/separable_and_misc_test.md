# 外部 AI 第二批提速想法：逐条实测（2026-11-06）

探针：`tools/opt_probe11.cpp`（不参与主程序构建）。数据：4096×2048 合成 10% 密度位图 +
2048×1024 **真实公式位图**（密度实测 10.00%）双份验证，所有对比都校验命中数完全一致。

## 0. 先排除「已经测过」的

| 想法 | 状态 |

| 17 位分块查表 | 已测：正确但 1.82 ns/区块（比直接乘 1.41 慢），放弃 |
| nibble 求和 mod 5 | 已测：4.29 vs 1.31 ns，慢 3.3×，放弃 |
| 多级筛选 / 双点哈希（m≤150） | 已测：位图 AND 全面胜出 |
| FFT / 卷积 | 已分析：位图 AND 只需 0.39 次操作/锚点，FFT 不可能更便宜 |
| Roaring Bitmap | 已分析：10% 均匀密度无收益 |
| LCG jump-ahead | 已分析：按行分块天然不重叠 |

| 大页 / perf | 平台不适用（Windows/MSVC） |
| 5×5 逆解（含线性 Δ 结构） | 上一轮已测：Z3 对 m≥9 不收敛；且 5×5 全世界期望仅 1.4e-12 个，**没有解可找** |

## 1. 可分离位图 AND（W+H 代替 W×H）—— **确认有效，是这批里唯一的大赢家**

做法：先做行内 AND（每行 W-1 次移位），把结果记作 R；再做行间 AND（H-1 次整行对齐 AND）。
总移位次数从 W×H 降到 W+H-2。

| 图案 | m | 全偏移 AND | 可分离 | 倍率 | 命中一致 |
|---|---|---|---|---|---|
| 3×3 | 9 | 0.077 ns/锚点 | **0.055** | 1.39× | 是 |
| 5×5 | 25 | 0.187 | **0.077** | **2.42×** | 是 |
| 12×12 | 144 | 1.161 | **0.163** | **7.08×** | 是 |
| 32×32 | 1024 | 7.467 | **0.421** | **17.7×** | 是 |
| 5×5（真实数据） | 25 | 0.184 | **0.074** | 2.50× | 是 |
| 32×32（真实数据） | 1024 | 7.207 | **0.419** | 17.2× | 是 |

**它直接改写上一轮的结论**：上一轮说「m≥200 时双点哈希反超位图 AND」——那只是在「全偏移 AND」
的前提下。加上可分离后，32×32 只要 **0.42 ns/锚点**，比双点哈希的 1.39 ns 还快 3.3 倍，
**位图 AND 的优势区间一直延伸到 1024 点以上**。

适用范围：**所有「每行图案相同」的矩形图案**（全绿 N×N、单行/单列、竖条纹都算）。
行与行不同的图案（棋盘、任意混排）需要按「不同行图案的种数」分别做行内 AND，再按行偏移组合，
成本 = 种数×W + H，仍然远低于 W×H。

## 2. 双点哈希连接：**不要用哈希表**

| 实现 | ns/锚点 |
|---|---|
| 位图位测试（现有做法） | **0.43**（完整两点+验证 1.39，见上轮） |
| 开放寻址哈希表（AI 建议） | **11.03** |

哈希表比直接位测试慢 **25×**：位测试只是一次 L1 命中，哈希表要插入 10% 的点 + 随机探测。
所以「用开放寻址替代 unordered_map」这个建议方向对，但**我们这个场景连哈希表都不该用**。

## 3. 差分生成 u(x)：**更慢**

| 实现 | ns/区块（含 LCG+mod10） |
|---|---|
| 预计算表查表（引擎现用） | **1.232** |
| 二阶差分递推 | 1.692（慢 37%） |

两个原因：
1. 引擎并不存「1 亿项 800MB 的 F 数组」，而是每行一个 `rowBase` + 一张 W 长的 xTail 表（≤40KB，常驻 L1/L2），
   所以内存带宽根本不是瓶颈；
2. `F = sext(t1) + sext(t2)` 两项必须**分别**在 mod 2^32 下差分再符号扩展
   （直接把两项加成一个 uint32 再扩展是错的，第一版就是这么对不上的），
   每区块多出 4~5 条整数指令，比一次表加载贵。

## 4. q 奇偶预筛：**更慢**

| 写法 | ns/区块 | 相对 |
|---|---|---|
| `q % 10 == 0`（编译器出魔术乘） | **1.351** | 1× |
| `(q&1)==0 && q%5==0` | 3.779 | 2.8× 慢 |
| 奇偶先行 `if (q&1) continue;` 再 `%5` | 2.840 | 2.1× 慢 |

`%10` 与 `%5` 都是一次魔术乘，奇偶判断是**额外**开销，不是替代。

## 5. q 对 x 各位的敏感性：**完全敏感**

翻转 x 的任意一位，q 的高 8 位 100% 改变（32/32 位全变）。
说明不存在「用 x 的高位粗筛、低位精判」的分层结构 —— q 对 x 是雪崩式的。

## 6. 5×5 全绿的线性 Δ 结构

AI 的推导是对的：`Δ_i = α_i·x + β_i·z + γ_i (mod 2^48)`，我们的 Z3 模型也是用平方展开
（`(x+dx)² = x² + 2dx·x + dx²`）把变量乘法从 m 个降到 2 个 —— 但实测 m=9 就不收敛。
而且密度摆在那里：5×5 全世界期望 1.4e-12 个，**不是算法慢，是没有解**。
若只要求「至少 k 个绿」，那正是本程序的**密度模式**（阈值 = k/25），已经支持，不需要逆解。

## 结论 / 建议

1. **值得做**：把严格匹配的「全偏移 AND」换成**可分离 AND**（行内 + 行间），
   5×5 快 2.4×、12×12 快 7×、32×32 快 17.7×，且逐位等价。
   端到端收益：5×5 时匹配只占扫描的 ~15%，预计整体提升 8~12%；大图案提升更明显。
2. **不做**：哈希表双点、差分生成、奇偶预筛、位敏感性分层、逆解。
3. 双点筛选保留「位测试」形式即可（m 小的时候位图 AND 更快，不需要它；大图案现在有可分离 AND 也不需要）。
