    [UTF-16]  史莱姆区块缓存 (*.cache);;所有文件 (*.*)   ← 「导入缓存」对话框过滤器

1.3 根因（v3.3.2 复核结论）

    * 缓存文件固定保存在**程序目录**（appDirPath()/slime_cache.cache）；
    * 而「导入缓存」对话框的第 3 个参数（起始目录）为 **空 QString** —— Qt 回退到
      进程工作目录 / 上次访问目录。用户从快捷方式或其它工作目录启动程序时，对话框
      落在别处，程序目录里的缓存文件自然「存在但看不到」，这就是任务书描述的现象。
    * 次因：过滤器只列 *.cache。若用户手里是更早的 Python 缓存（.pkl），或把缓存
      放在了别处，在对话框里也看不到（需手动切到「所有文件」）。
    * 说明：v3.1.1/v3.3.0 的保存名与过滤器**扩展名本身是匹配的**（都是 .cache），
      因此「扩展名不一致」不是本次 Bug 的成因；真正的问题是**对话框起始目录未定位**
      （外加历史格式未列入过滤器）。

【3】旧格式兼容矩阵（实际历史）

    .slimecache   v3.3.1+ 保存格式  → 直接加载（当前默认）
    .cache        v3.1.1~v3.3.0     → 直接加载；启动时若只存在旧文件则自动迁移为新格式（旧文件保留）
    .pkl/.pickle  v3.1.0 及更早     → Python pickle，**不能**直接加载：对话框可见并选中后
                                      给出提示，需用 scripts/convert_pkl_cache.py 转换
    .bin          任务书列举的假设格式 → 本程序**历史上从未使用**（无任何保存/加载代码；
                                       全仓库与全部历史二进制中均无 .bin 缓存相关字符串）
