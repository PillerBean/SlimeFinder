### 2.2 P0：缓存状态标签即时刷新（任务书 2.2）

**根因**：标签只在少数路径刷新（启动加载 / 导入 / 清除 / 版本切换），
**搜索完成后的写盘路径、分块增量合并路径、勾选变化路径**都没有刷新；
且文案未包含任务书要求的「共 N 个区块」。另外内存无数据但磁盘有缓存文件时也显示「未加载缓存」，
用户无法判断缓存到底在哪。

**修复**：`updateCacheStatusUi()` 文案改为
`缓存已加载，共 N 个区块（覆盖 R 个区域，约 X MB）`；磁盘态提示
`未加载缓存（磁盘上已有 slime_cache.slimecache，可点「导入缓存」或重启程序载入）`；
在所有缓存变更路径显式刷新（含 v3.3.3 新增的「使用缓存」勾选连接与分块覆盖分支）；
搜索写盘后状态栏提示 `缓存已更新：共 N 个区块`。

### 2.3 P1：GPU 加速临界值提示（任务书 3.1，方案 A 静态预判）

**实现**：`slime::GpuScan` 新增 `deviceName()/globalMemBytes()/computeUnits()`（默认安全实现），
`GpuScanAdapter` 从 `GpuSession::device()` 填充；GUI 侧
`gpuThresholdChunks()` 按 **`显存(MB) × 1000 ÷ (逻辑核数 × 0.85)`** 估算临界区块数，
源码注释给出完整标定依据（实测数据、K 的含义与调参方向）。

**实测**（本机 RX 6750 GRE 10224 MB / 12 线程）：
```
[UI自检] GPU=gfx1031（Advanced Micro Devices, Inc.） 显存=10224 MB 核数=12 → 临界值=1002352 区块
[UI自检] 小范围提示触发: total=16 状态栏="当前范围较小（16 区块，低于本机临界值约 100 万），建议关闭 GPU 加速以获得更快速度。"
```
* 临界值 1,002,352 与实测交叉点（0.4~1.0 M 区块）及引擎启用阈值 `SLIME_GPU_MIN_CHUNKS`（1<<20）一致；
* 勾选 GPU 时组内显示 `设备：gfx1031（…）｜ 本机估算临界值约 100 万区块。…`；
* 搜索前低于临界值 → 状态栏提示（已实测可见，且不会被「正在搜索…」覆盖：提示在 `startSearch()` 末尾写入）；
* 高于临界值不提示（条件分支只在 `total < 阈值` 时触发，自检断言边界）；
* **不做动态测量**：仅一次静态算术，勾选与搜索无额外耗时。

### 2.4 P1：进度分阶段 + 消除「未响应」（任务书 3.2）

* 阶段文字（纯函数 `progressStageText()`，GUI 与自检共用）：
  `正在扫描区块… X% ｜ 速度 … 万/秒 ｜ 预计剩余 M:SS` →
  `扫描完成，正在匹配图案…` → `正在匹配图案… X%` → `正在排序结果…` → `搜索完成（…可排序）`。
* **匹配在主线程吗？** 不在：搜索始终在 `SearchTask` 的后台 `std::thread` 中执行，
  扫描/匹配循环内均定期检查取消标志；主线程仅处理队列回调。
* **「未响应」真正原因**：匹配完成后主线程一次性创建最多 2000 张结果卡片（QLabel + 按钮），
  事件循环被占满。**修复**：改为「先收集 → 分批创建（每 40 条 + `processEvents`）」，
  期间显示 `正在生成结果列表… i / N`。
* **取消响应实测**（自检 13.7）：
```

[UI自检] 取消响应(运行中=1): 停止 8.9 ms
```
