# v3.1.1 验证与性能报告（verification_report_v311.md）

> **补丁记录（缓存修复，随 v3.1.1 交付；版本号不变，仅 Bug 修复，无地图等新功能）**
> 修复“基岩版大范围（≥全局预设/分块路径）搜索后缓存文件仅 ~1KB”问题。
> 根因：①分块路径对整区新增条目设 64M 上限、超限清空后仍整区声明覆盖 → 空文件；
> ②块内经典路径需 `omp_set_num_threads`，在 OpenMP 并行区内调用非法（崩溃/快速失败）。
> 修复：块间并行改为普通线程池（消除嵌套）；缓存改为“并行只收集（分块覆盖声明）→
> 结束后单线程统一并入”，并按 config 容量预算保留最新分块（分片式语义，内存有界）；
> 引擎 `cacheHandledIncrementally` 标志使 GUI 不再整区合并。验收：大范围缓存文件大小
> 与范围成正比、重载一致、判定抽查一致（单元测试 [12]），详见架构文档 §8。

- 被测版本：SlimeFinder v3.1.1（C++20 / Qt 6.11.2 / MSVC 19.51 / Release `/O2 /openmp /GL /LTCG`）
- 测试机：AMD Ryzen 5 5600（6C/12T），Windows 11 x64
- 范围：仅限“移除整图硬限制 + 用户确认 + 版本/关于信息”，判定逻辑零改动

## 2. 整图搜索实现与验证

- 移除面积/位图硬限制；超大范围自动切分 z 分块（单块 ≤16M words≈128MB，并行 ≤12 路），
  分块与经典路径**逐条一致**：单元测试 [11] 在强制多分块下对拍
  密度（含及时停止）、严格 2×2、旋转图案 → 最近 N 列表与 totalFound 完全一致；
- 经典路径（常规范围）代码不变：111 项参考对照全过、常规单元测试全过；
- 整图自动分块冒烟：W=3,200,000 × H=1,300（约 41.6 亿区块，超过原 40 亿硬上限），
  2×2 全绿最近 10 → 11.8 s 返回，内存平稳；
- 估算 API `estimateSearch()`：1024² 样本实测速率 → 外推整图耗时（含重叠与并行度），
  无界面自检覆盖（面积/窗口/速率/耗时字段自洽）；
- 性能参考（本机 12T）：整图仅扫描约 14.06×10¹² 区块 /（多核实测 ~3.1×10⁹/秒）
  ≈ 75 分钟量级 → 确认框按“本机实测”如实显示；任务书参考目标 ≤50 分钟系高性能多核
  机器的能力线，本机估算会如实更长（允许略超）。
