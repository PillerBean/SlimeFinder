# v3.4.10 进度与交付记录（更新历史重写）

> 任务书：`SlimeFinder v3.4.10 任务书：更新历史重写`（目标 + 约束 + 验收；Agent 自主执行）
> 约束：不改其他页面、不改功能逻辑、除五类标签外不引入绿色以外的强调色。

## 一、做了什么

### 1) 文本（`docs/update_history.md` = 文本源，与 C++ 数据同源生成）

- 全部版本按 `V<版本号> · <日期>` + `【分类】内容` 重写，**1.0.0 → 3.4.10 共 44 个版本**；
- **3.4.1 不列入**（别名包）；正式版仅 **V2.8.4 / V3.1.1 / V3.3.0**；无留档日期保留「（推测）」；
- 分类只用【新增】【修复】【优化】【调整】【移除】，顺序固定、空分类省略；
- 用描述词替代具体数字（如「密度搜索大幅提速」），去掉开发过程描述；
- **按用户最新要求严格按版本号排序**（原来 3.4.2 / 3.4.3 / 3.4.8 的排列会跳号，已修正为纯版本号序）。

### 2) 数据源（`src/gui/UpdateHistory.h/.cpp` 结构重做）

- 由「纯文本片段」改为**结构化数组**：`HistoryEntry { version, date, official, items[] }`，
  `items[]` 为 `{ tag, text }`；`updateHistoryEntries()` 供界面读取，`updateHistoryTextUtf8()` 仍供帮助对话框与自检。
- 分类顺序在构建时用 `stable_sort` 兜底，保证「新增→修复→优化→调整→移除」。

### 3) 界面（更新历史页重做，严格照任务书 §三 的 HTML）

- 折叠行：`▶/▼` 箭头 + `V版本号` + `日期` + 右侧「正式版 / 测试版」；
- **点击整行任意处**展开/收起（`MainWindow::eventFilter` 统一处理），**最新版默认展开**；
- 正式版浅绿底 `#F3F8F3`（深色 `#182018`）、无左线；测试版浅橙底 `#FFF3E0`（深色 `#2A1F12`）+ 3px 橙左线
  （浅色 `#F0B27A` / 深色 `#8A5A2B`）；悬停浅绿 `#E8F5E9` / `#1E2A1F`；
- 五类标签配色：新增 `#2E7D32`、修复 `#B26A00`、优化 `#1565C0`、调整 `#6A1B9A`、移除 `#B71C1C`；
- `QScrollArea` 可滚动；**移除排序按钮**（任务书要求严格按版本号排序）。

### 4) 顺手修正

- 深色主题原本缺少 `#updateBadge` 的深色规则（两套 body 里是同一行浅色值）⇒ 一并补齐。
- 自检的「更新历史」断言全面更新：折叠行数、版本号严格排序、3.4.1 不得出现、正式版恰 3 个、
  文本行格式、分类合法性、无链接/密码。
