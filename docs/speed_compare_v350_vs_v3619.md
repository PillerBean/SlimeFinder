# 3.5.0 vs 3.6.19 效率对比（2026-11-05）

测试机：AMD Ryzen 5 5600（6C/12T，4.4 GHz 睿频）、16 GB、AVX2 可用、无 AVX-512。
两版均为官方 Release 构建，同机同参数、同进程先后运行取多次最小值（`--bench` 取 2~3 次最好成绩）。

- 3.5.0：`dist/_archive/SlimeFinder-3.5.0-win64.zip` 解包后的 `slime_tests.exe`
- 3.6.19：当前 `build/slime_tests.exe`

## 一、内置基准（`--bench`，同一模板）

| 基准行 | 3.5.0 合计 | 3.6.19 合计 | 倍数 |
|---|---|---|---|
| Java 1000×1000 单核 | 3.5 ms | 1.1 ms | **3.18×** |
| Java 1000×1000 多核 | 3.3 ms | 1.9 ms | 1.74× |
| Java 10000×10000 单核（1 亿区块） | 350.9 ms | 116.4 ms | **3.01×** |
| Java 10000×10000 多核 | 77.3 ms | 20.3 ms | **3.81×** |
| 基岩 2000×2000 单核 | 140.0 ms | 134.8 ms | 1.04× |
| 基岩 2000×2000 多核 | 30.2 ms | 26.6 ms | 1.14× |
| 密度 g=5 thr=0.3 2000×2000 多核 | 8.1 ms | 5.7 ms | 1.42× |
| 严格 2×2 全绿 2000×2000 多核 | 3.5 ms | 2.1 ms | 1.67× |

分阶段看扫描本身：
- 3.5.0：1 亿区块 197.8 ms ≈ **505 M/s**（单核）
- 3.6.19：1 亿区块 110.5 ms ≈ **905 M/s**（单核）⇒ **1.79×**（AVX2 16-lane 判定）
- 多核：34.1 ms → 17.3 ms（**1.97×**）

## 四、真实使用形态（CLI，10000×10000 = 1 亿区块，最近 5 个结果，4 线程）

| 场景 | 3.5.0 | 3.6.19 | 倍数 |
|---|---|---|---|
| 密度 g=5 thr=0.3 | 134 ms | 88 ms | **1.52×** |
| 密度 g=3 thr=1.0 | 134 ms | 46 ms | **2.91×** |
| 密度 g=3 thr=1.0 单线程 | 348 ms | 112 ms | 3.11× |

反例（重要）：**不限结果数量**（CLI 默认 `targetCount=∞`，1 亿区块命中共 150 万+）时：
- 3.5.0 6793 ms vs 3.6.19 6721 ms ⇒ **几乎无差别**。
- 原因：瓶颈从"搜索"变成"把上百万条结果写进结果堆"，两版这段代码相同。

## 五、环形搜索（GUI 自检 400×400 区块场景）

| 场景 | 3.5.0 | 3.6.19 |
|---|---|---|
| 大范围环形（400×400） | 0.09 s | 0.10 s |

差别在噪声范围内 —— 环形规划在 3.6.x 没有算法级提速（3.6.9 只省了每带约 24 MB 的无效写入）。

## 六、结论

1. **扫描是最大赢家**：Java 单核 505 → 905 M/s（1.79×），多核 1.97×；1 亿区块整轮 3.01×（单核）/3.81×（多核）。
2. **密度搜索是第二赢家**：`最小密度=1.0` 走 AND 快路后 9.8 ms（相对 3.5.0 的 161.6 ms 是 16.5×）；一般阈值靠 SIMD 窗口和拿 1.42~1.52×。
3. **严格图案、基岩版、环形规划基本没变**：严格图案早已到字并行上限；基岩是 MT 递推的吞吐上限；环形规划受群系采样支配。
4. **收益取决于"要找几个结果"**：找最近的 N 个（默认 5）提升 1.5~3×；若要收集全部命中，瓶颈变成结果写入，两版一样慢。
