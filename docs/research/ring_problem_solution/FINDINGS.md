# 环形覆盖反例问题：已解决的、未解决的、以及该改的

> 对应文档：`docs/planning/ring_counterexample_problem_paper.docx`（2026-11-21 版）
> 本文所有结论都有脚本可复现，见第 7 节；所有数字都是精确整数运算（无浮点近似）。

---

## 0. 三句话结论

1. **问题 1 有平凡解**：`N=3, K=1, X=单个史莱姆区块` 就使 `F(X)=1`（`V=253 < M=256`）。
   论文 §6 的小模型实验之所以 0 失败，是因为 `g=3/7, R=32` 让 3×3 抛光恰好覆盖了环带所在的
   chunk 范围；真实参数 `g=15, R=128`（环带半径 = 8 个 chunk）时，3×3 抛光差得很远。
2. **去掉并列（要求分数唯一）仍然有反例**：`N=36, K=1, 337 个区块`，`V=33426 < M=43008`
   （22.3% 的价值差，不是擦边）。机制不是 tie-break，而是**预筛的“浪费区”**：
   15×15 窗口内有 13 个 chunk 的质量对 `C` 毫无贡献、44 个只有部分贡献，却都全额计入 `S`。
3. **Q3/Q4 的真正难点不是“稀有”，而是“临界”**：真实参数下 `M/256 ≈ 58`、`t_K = 55`、
   `t_K + β/256 ≈ 65`，三个数在同一量级上相撞。`P(F)` 对`全局最优所在 chunk 的方形分数`
   极其敏感（差 2~3 分，`P(F)` 可以从 ~1 变到 ~1e-30）。所以论文要求的
   “`P ≤ 10^-s` 的严格上界”不是这个问题的正确提法，正确对象是 **rank 分布 / 边界穿越概率**。

## 1. 精确模型（已实现并与逐格暴力交叉验证）

平移不变性把问题化成**一个有限核的卷积**：`w_v(c)` 只依赖
`(v − chunk(c), c mod 16) ∈ Z² × [0,16)²`，所以只有 289×256 个不同的权值。

```
C(v,o) = Σ_δ X[v+δ] · W[δ, o]          # 256 个 17×17 核的卷积
S(v)   = 15×15 box sum
```

实现：`ring_problem/ring_model.py`。核表与逐格暴力在 289×5 个 (δ,o) 上完全一致；
`C`、`V`、`M`、`S` 都用第二种求和路径独立复核过（`verify_counterexample.py`、
`verify_final.py`）。

几何实测（r=24, R=128, s=16，中心在 chunk 内偏移 (8,8) 或 (7,7) 时）：

| 量 | 值 | 说明 |
|---|---|---|
| 环带格数 `Σ_δ W[δ,o]` | 49,644 | 内半径 24、外半径 128 |
| `w>0` 的 chunk 总数 | 240 | 其中 **28 个在 15×15 窗口之外** |
| 窗口内 `w=256`（整块在环内） | 168 | 只有这些能“1 分换 256 格” |
| 窗口内 `0<w<256` | 44 | 边界 chunk，部分贡献 |
| 窗口内 `w=0` | 13 | **真正的免费分数** |
| `β_max = max_c Σ_{u∉W(v)} w_u(c)` | **2,546** | 窗口外看不见、但计入覆盖的质量 |

> **论文 §5 的表本身没错，但 §5 用它做的推论错口径**：那张表是“chunk 中心距离”的划分
> （论文原文也写了 `chunk-center lattice`），而目标函数 `C` 用的是**格计数**。
> 用中心距离口径会得到“窗口外只有 4 个环带 chunk、1,024 格”；
> 真实格计数口径下是 **28 个 chunk、1,882–2,546 格**，而且窗口内的“浪费区”也不是 41 个
> 全零 chunk，而是 `13 个 w=0 + 44 个 0<w<256`。这两个数字直接进入第 3 节的判据，必须改。

## 2. 问题 1 的三个答案

### 2.1 最小 `N`：`N=3, K=1, X = 角上一个区块`

- `N=1`：穷举 2 个配置，0 失败（`M=V=0`）。
- `N=2`：穷举 16 个配置，0 失败。
- `N=3`：`X[0,0]=1` → `V=253 < M=256`，`F=1`。

原因：单区块时 `S≡1` 在窗口内所有 chunk 上并列；字典序 tie-break 取到 `q=(0,0)`；
`N(q)` 在角上被裁剪成 4 个 chunk，而 `M` 的最优中心在 `q` 的另一侧。
`3×3` 抛光 vs 半径 `R/s=8` 的环带 —— 够不到。

### 2.2 自然尺度：`N=8, K=1, X = 一个区块在 (7,7)`

`V=180 < M=256`。真最优中心在 chunk `(0,4)`、偏移 `(9,14)`，即方块 `(78,9)` ——
不在被评估的 4 个 chunk 里。16×16 的放置实验里约三分之一位置会失败（`probe_single_chunk.py`）。

### 2.3 **无并列**（唯一最大分数）的反例：`N=36, K=1, 337 个区块

```
隐藏中心 v*=(10,10)：取全部 168 个“整块在环内”的 chunk
    C(c*) = 168 × 256 = 43,008,   S(v*) = 168
竞争 chunk q=(28,28)：169 个 chunk，贪心+局部搜索最小化
    Φ = max_{c∈B(q)∪B(N(q))} C(c) = 33,426,   S(q) = 169  （唯一最大）
结果：top-1 = q，v* 排名第 2，不被评估
    V = 33,426 < 43,008 = C(c*) ≤ M      →  F = 1，差距 22.3%
```

这个反例**不依赖 tie-break**（`S(q)=169` 严格大于第二名 168），
所以即使把 `T_K` 改成“所有并列 chunk 都算”也依然成立。

**机制（waste asymmetry）**：`S` 数的是“个数”，`C` 数的是“格数”。
把质量堆在 13 个 `w=0` 的 chunk 和 44 个边界 chunk 上，可以拿到很高的 `S`
而 `C` 很低；反过来，把 168 个 `w=256` 的 chunk 填满，`S` 每加 1 就换 256 格。
于是 `256·S_hidden + β` 可以压过 `Φ_top`，只要 `S_hidden` 只比 `S_top` 小一点点。

## 3. 正确的结构定理（建议替换论文 §5）

**引理 1（效率上界）** 对任意 `X`、任意中心 `c ∈ B(v)`：

```
C(c) ≤ 256·S(v) + β(c),        β(c) ≤ β_max = 2,546
```

**引理 2（安全性判据）** 记 `t_K` 为第 K 名方形分数。则

```
M ≥ 256·t_K + β_max   ⟹   F = 0（必然成功）
```

证明：全局最优 `c*` 在 chunk `v*`，由引理 1 有
`S(v*) ≥ (M−β_max)/256 ≥ t_K`，故 `v* ∈ TopK`，`c*` 一定被评估。

> 这是整个问题**唯一干净的抓手**：失败只可能发生在 `M < 256·t_K + β_max` 时。
> 它同时说明“M 很大就自动安全”，把 Q3/Q4 化成一个**两个极端值的竞争**。

**引理 3（有限化）** 由平移不变性，失败的存在性等价于一个有限 min-max 问题：

```
∃s: 256·s + β_max > ρ(s+1),
ρ(s) = min_{|A|=s, A⊆W(q)} max_{c∈B(N(q))} Σ_{u∈A} w_u(c)
```

`ρ` 只依赖几何，可精确/近似计算。这把 Q1/Q2 从“碰运气搜索”变成“算一条前沿”。
（本报告的 337 块反例就是 `s=168` 处的前沿点：`256·168+β > ρ(169) ≤ 33426`。）

## 4. Q3 / Q4：为什么难，以及怎么做

### 4.1 尺度对比（真实参数 `N=3.75e6, K=4000, p=0.1`）

| 量 | 值 | 来源 |
|---|---|---|
| `t_K`（第 4000 名方形分数） | **55** | 精确二项尾：`P(Binom(225,0.1)≥55)=3.4e-10`，`K/N²=2.84e-10` |
| `256·t_K + β_max` | **16,626**（= 64.95 个 chunk 单位） | 引理 2 |
| `M` 的极端值 | **14,718 – 15,700**（57.5 – 61.3） | 单中心精确 Chernoff 速率 + 有效独立中心数 |
| 全局最优 chunk 的分数下界 `(M−β)/256` | 47.5 – 51.4 | 引理 1 |
| 它的排名 `≈ N²·P(S ≥ ·)` | `10³ – 10⁵` | 名次与 `K=4000` 同量级 |

**更锋利的等价**：设 `v*` 是全局最优 `c*` 所在的 chunk。若 `rank(v*) ≤ K`，则 `v* ∈ TopK`，
`c*` 必被评估，于是 `V ≥ C(c*) = M` 且 `V ≤ M`，即 `V = M`，**不可能失败**。所以

```
F = 1  ⟹  rank(v*) > K.
```

而 `rank(v*) ≈ N²·P(S ≥ S(v*))`，对 `S(v*)` 极度敏感：

| `S(v*)` | 51 | 53 | 54 | **55** | 56 | 58 | 60 |
|---|---|---|---|---|---|---|---|
| `rank` | 3.1e5 | 4.0e4 | 1.4e4 | **4,799** | 1,600 | 166 | 16 |

`K=4000` 正好卡在 `S(v*)≈55` 这条线上。也就是说：**`P(F)` ≈ `P(S(v*) ≤ 55)` ≈ `P(M ≲ 14,100)`**。
三个数（58 / 55 / 65）撞在同一量级上，差 2~3 分，排名就从 `10²` 跳到 `10⁵`。
**这就是“极其难”的真正原因：不是 10⁻⁵⁰ 的稀有事件，而是一个 ill-conditioned 的临界竞争。**

### 4.2 §6 的实验为什么没有信息量

`N=4`（`g=3`）和 `N=8`（`g=7`）时 `R=32` 只有 2 个 chunk，`K/N²` 是 `10⁻²` 量级；
真实参数 `K/N² = 2.8×10⁻¹⁰`，差 7–9 个数量级，且 `R/s` 从 2 变成 8。
“0 失败”既不能外推，也不能当作 `P` 小的证据。

### 4.3 可行的严谨路线

**上界**（推荐）：用引理 2 把事件降维

```
P(F) ≤ P(M < 256·t_K + β) = Σ_t P(t_K=t) · P(M < 256t+β | t_K=t)
```

右端两个因子都只依赖**局部窗口**（`S` 是 225 个独立变量、`C` 是 240 个加权和），
可以用“条件化 `t_K` + 局部依赖 + Chernoff”处理；这比原问题里 `(c*, q)` 的联合事件小得多。
注意 `t_K` 本身要用 Markov/切诺夫控制其下尾（不能假设它是常数）。

**下界**：把 337 块构造成参数族 `(t, s)`，算它的 Bernoulli 质量；
但注意“最小 `|X|`”≠“最大概率质量”——`p^{337}` 本身可以忽略，
真正的下界来自更“便宜”的失败簇（需要在 `s ≈ t_K` 附近做前沿搜索）。

**精确计算**：小 `N` 可以沿 chunk 行做 DP（状态是最近 17 行的质量分布），
`N=8..12` 可行；真实尺度只能 importance sampling（证据，不是证明）。

**我的判断**：`P(F)` 在真实参数下大概率**不是** `10^-s`（`s` 很大）的形式，
而是 1%–50% 量级、且对参数极敏感。论文若要提交，Q4 应改成
“求 rank 分布 / 边界穿越概率”，或改成“设计预筛使 `P(F) ≤ ε`”。

## 5. 工程含义

1. **方形预筛在真实参数下不可修补**。要保证安全需精修所有 `S ≥ t_K − Δ` 的 chunk，
   `Δ ≈ t_K − (ρ(t_K) − β)/256 ≈ 0.2·t_K + 8`；`p=0.1` 时这条带会包含
   `N²·P(S ≥ 0.78·t_K)` 个 chunk，天文数字 → 不可能。
2. **正确方向是几何加权预筛**：用 annulus kernel 的粗粒度卷积
   （代码里已有 `subOffsetKernels`），浪费区消失，误差只剩离散化，可控可证。
   方形预筛只适合做“粗筛的第一层”，后面必须接一层几何正确的筛选。
3. 若要保留 `3×3` 抛光：把 `R/s = 8` 的环带半径覆盖进去需要 17×17 抛光，代价不可接受
   → 所以“扩大抛光”不是出路，“换预筛”才是。
