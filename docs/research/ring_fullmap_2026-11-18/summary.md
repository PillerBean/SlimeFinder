## 解释

1. **基准点已经是强局部最优**
   - 1 方块邻域、4 方块邻域、±512、±4096、±16384 都没有更好点。
   - 全 4000 种子精算、全量抛光也没有超过。

2. **低阈值种子不是更好，而是更差**
   - threshold 从 0.18 降到 0.10 后，种子更多但候选集被低质量区域淹没。
   - 即使放开精修上限到 20000，结果仍低于基准。

3. **方形窗口 15 是最优窗口**
   - 7、11、14 都低于或等于基准；14 同分但更慢。
   - 21 超出 GPU 预筛支持范围，回退抽样，明显变差。

4. **加权目标几乎退化为有效格数**
   - 基准 coveredWeight/coveredBlocks = 14324.516/14387 ≈ 0.9956。
   - 该区域群系权重接近 1.0，所以当前加权与不加权排序差别很小。

5. **时间瓶颈**
   - 方形预筛约 215s，规划/精修/严格统计约 10ms。
   - 因此参数调整几乎不改变总时间；要显著改变时间只能改预筛本身。

## 尚未验证、最值得继续的方向

1. **GPU 环形预筛**
   - 当前 GPU 预筛只算正方形。
   - 若直接算“外方窗 - 内方窗”或环带核，可能找到方窗漏掉的环形候选。
   - 预计仍是 200s 量级，但需要修改 GPU kernel。

2. **粗网格 FFT/卷积候选**
   - 64 方块粗网格全图 CPU 约 10h，GPU 估计 20–40min，超出单次 20min。
   - 只能做更粗网格或分块 GPU FFT，精度/耗时需权衡。

3. **方形上界 + 分支定界**
   - 可证明性方向，不是本轮质量上限方向。
   - 需要先有更强的初始解和上界。

## 当前判断

```text
在“方形预筛 + 1 格精修”框架内，基准已经接近该框架的质量上限。
继续调方形阈值/窗口/种子数不会提高 coveredWeight。
要突破，必须改变预筛核：从方形密度改成环形/环带密度。
```
