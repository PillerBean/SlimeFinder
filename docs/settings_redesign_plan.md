# 结果要求设置重构（快捷方案 + 自定义方案）规划 v2

> 背景：3.9.x 陆续加入了「找够就停 / 智能范围 / 最优候选（待做）/ 两级筛选（待做）/ GPU 图案流式 / 缓存优先」
> 等开关，结果区开关数量已让用户难以理解互相的语义与冲突。本规划把「结果要求」拆成
> **快捷方案（预设）+ 自定义（高级）** 两层，并让引擎开关由**单一映射**生成。
>
> **v2 修订（用户拍板）**：GPU 相关开关**不进入任何方案**，保持独立开关。

---

## 一、核心原则（v2）

1. **方案只控制「会改变结果的开关」**：模式、目标数量、阈值/图案、停止策略、最优候选、智能范围、精度算法。
2. **GPU / 线程 / 内存 / 缓存容量等「只影响速度、不改变结果」的设置，永远独立**，方案不读取、不写入、不记忆它们。
   * 不变式（有实测支撑）：同一方案在 GPU 开/关下结果**逐项一致**（已有 probe35/40 的 CPU↔GPU 对拍）。
3. **单一真相**：界面不逐项拼 `SearchOptions`，而是 `SearchPlan → SearchOptions` 唯一映射 + `RuntimeEnv`（GPU/线程等）独立注入。
4. **预设可退化**：用户改动任一项 → 自动切「自定义」并显示「已修改：X、Y」，不偷偷改回。
5. **向后兼容**：旧 config 字段全部保留读取；GPU 字段照旧独立持久化。

## 二、现状盘点：15 个开关，按「是否改变结果」重新切分

| 分组 | 开关 | 是否改变结果 | 归属 |
|---|---|---|---|
| 结果要求 | 模式（密度/严格图案） | 是 | SearchPlan（方案控制） |
| 结果要求 | 目标数量 targetCount | 是 | SearchPlan（方案控制） |
| 结果要求 | 最小密度 minDensity | 是 | SearchPlan（方案控制） |
| 结果要求 | 图案 + 方向锁定 | 是 | SearchPlan（方案控制） |
| 结果要求 | 找够就停 stopAtTarget | 是（complete 与否） | SearchPlan（方案控制） |
| 结果要求 | 智能范围 smartRange | 是（顺序/停止） | SearchPlan（方案控制） |
| 结果要求 | 最优候选（待做） | 是 | SearchPlan（方案控制） |
| 结果要求 | 精度算法（精确/分层/估算/保守） | 是（估算可能漏检） | SearchPlan（方案控制，高级） |
| 结果要求 | 分层块/比例、采样步长 | 是 | SearchPlan 高级子项 |
| 速度 | **GPU 加速总开关** | **否** | **独立开关** |
| 速度 | **GPU 图案流式** | **否** | **独立开关** |
| 速度 | **GPU 占用率上限** | **否** | **独立开关** |
| 速度 | 线程数 / CPU 上限 / 内存上限 | 否 | 独立（设置页） |
| 速度 | 使用缓存 / 构建缓存 / 缓存容量 | 否（构建模式本身不产结果） | 独立（设置页） |

> 「基岩攒缓存」不进入方案：它本质是**构建缓存任务**（没有结果），放在独立操作入口。

## 三、预设方案（5 个，全部不含 GPU/速度设置）

| 预设（仅密度模式） | 一句话 | 方案内设置 |
|---|---|---|
| **快速找最近 N 个**（默认） | 在起点附近要 N 个符合阈值的 | 密度模式、阈值生效、找够就停 **开**、智能范围 **开**、精确算法 |
| **找全部候选** | 要区域内所有符合阈值的结果 | 密度模式、阈值生效、早停 **关**、智能范围 关 |
| **最优 N 个（忽略阈值）** | 不知道阈值设多少，先看看最好的是什么样 | 最优候选 **开**、阈值置灰、早停关、智能范围关、精确算法 |
| **大范围粗筛** | 先花很少时间看大概 | 密度模式、估算算法、早停关、结果带「估算可能漏检」徽章 |

「自定义」= 全部结果类开关按现状展示（高级折叠区）。

> **图案模式没有图案模板、没有匹配要求开关，但有 2 个「结果要求方案」**（用户拍板）：「找最近 N 个（提前停止）」与「找全部候选」。
> 即：**方案数量与可用项由模式决定**（密度 4 种 / 图案 2 种），左列顺序固定为 **模式 → 方案 → 参数 → 停止方式**。
> 切到图案模式时隐藏方案下拉与密度阈值行，只保留：图案编辑器、方向锁定、目标数量、找够就停、智能范围。
> 详见 `pattern_search_ui_plan.md`。

## 四、GPU 开关：独立、常驻、与方案正交

**界面形态**：独立的「加速」区（与「结果要求」区分离，任何时候可见）：

```
┌ 结果要求 ──────────────┐   ┌ 加速（独立开关，不影响结果） ┐
│ 方案：[快速找最近 N ▾]  │   │ ☑ 使用 GPU 加速              │
│ ……                     │   │ ☐ GPU 图案流式（N/I 未验证） │
│                        │   │ GPU 占用率上限：[100%]        │
└────────────────────────┘   └──────────────────────────────┘
```

规则：
1. 方案切换**绝不修改**任何加速开关；
2. 加速开关变化**不触发**「已修改」提示、不改变方案名；
3. 加速区带常驻说明：「只影响速度，不影响结果；GPU 与 CPU 结果逐项一致（已对拍验证）」；
4. GPU 不可用/失败时，在**过程可视化面板**显示「本次走 CPU：原因 X」，而不是弹窗打断；
5. 结果区不出现「GPU 结果」字样（可选显示耗时来源）。

## 五、冲突自动裁决表（仅结果类开关）

| 组合 | 裁决 |
|---|---|
| 最优候选 + 阈值 | 阈值置灰、显示「已忽略」 |
| 最优候选 + 找够就停 | 早停置灰、显示「本模式不提前停止（可选分层密度剪枝）」 |
| 最优候选 + 严格图案 | 整项置灰 + 原因（最优候选只属于密度模式） |
| 最优候选 + 估算算法 | 强制精确算法（估算可能漏检） |
| 最优候选 + 缓存优先 | 关闭缓存优先（缓存是速度项，其隐藏语义会破坏全局最优） |
| 图案模式 + 密度阈值/方案下拉/算法选择 | 直接隐藏（不是置灰），图案模式没有这些概念 |
| 估算 + 找够就停 | 允许，但结果标「估算可能漏检」 |
| 构建缓存 + 目标数量/早停 | 构建为独立任务入口，不在此冲突 |

> 注：缓存优先属「速度项」，但它有一个**会影响结果的隐藏语义**；因此本规划把它从结果区彻底移出，
> 并在最优候选方案下**由引擎自动禁用**，在过程面板说明「已忽略缓存优先以保证全局最优」。

## 六、技术设计

```
struct SearchPlan {                 // 只含「改变结果」的项
    Mode mode;                      // Density / Strict
    bool ignoreThreshold;           // 最优候选
    int64_t targetCount;
    StopPolicy stop;                // Early / Full
    bool smartRange;
    Pattern pattern; bool directionLocked;
    double minDensity; int gridSize;
    Algorithm algorithm;            // 高级
    int layerBlock; double layerRatio; int sampleStep;
};
struct RuntimeEnv {                 // 独立开关，方案不可见
    bool gpuEnabled; bool gpuPatternStream; int gpuLimitPercent;
    int threads; int cpuLimitPercent; int64_t memLimitBytes;
    CacheMode cache; int64_t cacheBudgetBytes;
};
SearchOptions toOptions(const SearchPlan&, const RuntimeEnv&);   // 唯一映射，单测覆盖
SearchPlan fromPreset(PresetId);
PresetId detectPreset(const SearchPlan&);                       // 不参与判定：RuntimeEnv
QStringList explainConflicts(const SearchPlan&);                // 驱动置灰/横幅/日志
```

## 七、分阶段实施

| 阶段 | 内容 | 验收 |
|---|---|---|
| **A. 模型先行（不改 UI）** | `SearchPlan`/`RuntimeEnv` 拆分 + `toOptions()` + 单测 | 映射出的 `SearchOptions` 与现状逐字段一致；**断言方案不写任何 GPU 字段** |
| **B. 预设 UI（仅密度）** | 方案下拉 + 摘要 + 高级折叠 + 冲突置灰 + 独立「加速」区；图案模式隐藏方案/阈值/算法；config 迁移 | GUI 自检新增 4 方案用例 + 图案模式面板断言；「切方案不改变 GPU 开关」断言 |
| **C. 接入新功能** | 最优候选、两级筛选、排序视图走同一模型（只进高级区） | GPU 开/关两态下每方案结果逐项一致 |
| **D. 收尾** | 用户手册「怎么选方案」+ i18n + 更新历史 | 全量回归 + 性能基线不退化 |

## 八、验证要点（新增）

1. **正交性测试**：遍历 4 方案（密度）× GPU{开,关} × 2 环境（有/无可用 GPU）→ 结果逐项一致；图案模式另测「无预设、结果按距离排序」。
2. **方案隔离测试**：对每个方案应用后读取 `RuntimeEnv` 全部字段 → 必须与切换前完全相同；
3. **冲突裁决测试**：每个冲突组合 → 置灰状态与文案符合裁决表；
4. **回归**：旧 config（含 GPU 字段）读取后行为不变。

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| GUI 自检快照大面积变化 | 阶段 B 一次性改，自检按「方案 × 关键字段 × GPU 状态」断言 |
| 用户以为方案会动 GPU | 加速区独立 + 常驻说明 + 自检断言方案不写 GPU |
| 预设与引擎语义漂移 | 每个预设配执行断言；`toOptions(preset)` 必须通过裁决表 |
| 新功能继续膨胀结果区 | 新功能一律先进高级区；预设数量上限 6 |
