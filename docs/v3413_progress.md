### 改了什么

| 文件 | 改动 |
|---|---|
| `src/core/PerfLog.h` | `CpuSampler` 加 `std::mutex`（采样状态只允许一个线程改）；新增三参重载，同时给出两个口径；`m_cores` 默认值 1 → **0** |

| `src/core/SlimeEngine.cpp` | 两个调用点改用新重载（分块路径的块收尾处 = 多线程并发调用点）；经典路径 summary 追加 `cpuAllEnd=` / `cores=` |
| `tests/test_slime.cpp` | 新增**单元组 [27]**：8 线程并发轰同一个采样器，断言「越界 0 次 + 两口径自洽」；顺序采样忙等断言 `all≈100%` |

### 根因（两条，都是代码实证）

1. **采样器非线程安全**：`m_cpu100ns` / `m_ms` 是普通成员，而分块路径的**每个块工作线程**都会调用它
   （`SlimeEngine.cpp` 块收尾处每 5 秒一次）⇒ 两个线程同时读写同一对基准值，
   `dCpu/dMs` 组合毫无意义 ⇒ 日志出现 `cpu=18750%`（12 核机器物理上限 1200%）。
2. **单元组 [27] 立刻抓到的隐性缺陷**：`m_cores` 默认值是 **1**，而初始化条件是 `if (m_cores <= 0)`
   ⇒ **永远不会被赋值**，于是 `cpu=` 输出的其实是「各核占用之和」（0~100×核数）而不是「相对全部逻辑核」。
   这就是历史日志里 CPU% 远超 100 的第二个来源（任务书也把合理范围写成 0~100×核数，与此吻合）。
   现在：`m_cores` 默认 0，首次采样真正取逻辑核数；`cpu=` 恒 0~100，`all=` 恒 0~100×核数，两者自洽（`all = cpu × 核数`）。

### 连锁反应修复（任务书第四节预警的正是这一类）

1. **缓存读写竞态（崩溃）**：块数 2→47 后，工作线程的「缓存命中填充 / isSlime / covers」与归并线程的写（`ensureRange` 重分配向量、`m_outliers` swap）并发 ⇒ **6 次运行 2 次 0xC0000005**。
   修复：`SearchOptions::cacheReadMu`（分块路径把 `cacheMu` 交给工作线程，仅构建模式）＋ 读到的位图行**拷贝**到本线程缓冲；`covers()` 与命中段查询整段持锁。**8 连跑 0 崩溃**，段墙钟进一步降到 ~2.5 s。
   排除的第一版方案（工作线程完全不读缓存）虽不崩，但改变了「覆盖声明/条目」簿记，导致 9 条既有断言失败 ⇒ 已放弃。
2. **块边界条目重复计入**：块数据域末尾 hMax-1 行属下一块锚点行域，两块都收集 ⇒ 同一点进 outliers + 位图 ⇒ `entryCount` 虚高且随归并顺序波动（±224）。修复：`collectSkipZ0/Z1`（只有末块收集尾部行）⇒ `entryCount == 真值` 恢复。
3. **既有断言与新几何的耦合**：[5]/[12] 断言的是「2 块几何 / 相邻块声明不重叠」这类**分块语义**，已用 `SLIME_CHUNK_TARGET=0` 钉住旧几何；新几何由 [25]/[28] 与 44G 对照台覆盖。

**当前状态**：111/111 ✅、内核 19 项 ✅、GUI 自检 ✅、崩溃 0/8 ✅；**单元测试还剩 5 项断言待修**（[5] 小缓存覆盖小区域、[12] 第 1/2 块锚点行域声明 + 缓存路径一致性、[22] 跳过填充一致性、[25] 撤掉误加钉住）——修完才进第 5 步全量回归与第 6 步打包。

## 第 3 步门槛通过 + 第 5 步部分回归（✅）

**单元测试 28 组全部通过**（含 [27] 采样线程安全、[28] 归并调度无关性）。修掉的最后三处：

1. **我引入的「位图行拷贝缓冲」是 runImpl 内所有 OpenMP 线程共用**的 ⇒ 并行填充互相覆盖 ⇒ 命中缓存的搜索读到错行（[12]/[22] 的结果一致性断言失败）。改为 `static thread_local` ✓ 一次修好两处。
2. **[28] 线程数不同 ⇒ 块数目标不同**（target = 4×并发）⇒ 区域划分本就不同，不能逐矩形比位图；改为**语义等价**判据（覆盖域一致 + isSlime/lookup 抽样一致）；等线程数的「解耦 vs 内联」仍是逐字位图比较。
3. **构建模式容量上限的漏报**：块变小后单块位图可能始终小于预算字节数，只靠 `sizeBytes()` 判定会漏 `hitCacheBudget`；准入关闭（条目 ≈ 预算/8 字节）本就是「预算装不下」的同义事件 ⇒ 构建模式下同时置 `budgetStop`。
