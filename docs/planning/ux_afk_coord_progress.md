# 搜索页顺序 / 建议挂机坐标 / 地图按高度覆盖 / 环形进度（2026-11-28）

用户反馈（本轮）与处理记录。四项 UX 改动的设计与计算依据，避免下次重新推导。

## 1. 搜索页顺序：先选“搜什么”，再选“怎么搜”

问题：原顺序是「A 搜索方式 → B 结果要求」，但 A 的候选池由 B 里的“图案/密度 + 区域形状”决定，
用户要来回上下滚动。

目标顺序（4 个顶层组，从上到下）：

```text
① 搜索内容：图案 / 密度；区域形状（方形 / 环形）；方案预设；图案编辑器 + 方向锁定
② 搜索方式：环形 = 四档扫描方式；图案 / 正方形 = 匹配算法与参数（候选池由 ① 决定）
③ 结果要求：搜索范围、最低密度/忽略阈值、正方形网格、环形模拟距离/内外半径/群系权重、
            目标数量 / 达到即停 / 智能范围
④ 执行设置：线程 / GPU / 内存预算 / 缓存管理
```

实施：分支 `flow-ui-order`（独立 worktree），只做分组重排 + 可见性 + i18n + GUI 自检，
不改结果列表/环形 worker/地图，最终合并回 `flow-integration`。

## 2. 结果列表“建议挂机坐标”（XYZ 合并一列）

用户要求：**只在结果列表显示其建议挂机坐标即可**（不改变结果排序）；XYZ 合并只占一列。

### 2.1 计算依据（先在工作日志/研究文档里翻到的规划）

- `docs/research/ring_problem_solution/height_region_prototype.md`：三维球壳模型
  `24 ≤ 三维距离 ≤ 128`（内半径 24、外半径 128），平台 = 基岩底层；离散方块/群系权重模型；
  **H > 24 由 H = 24 支配**（H=24 时内孔半径=0，外半径更小）⇒ 高度只需扫 0..24。
- `docs/research/ring_problem_solution/height_fullmap_test.md`：
  - 最终评分必须用**块级群系权重**（chunk 级近似会高估 3%–5% 并改变最佳高度）；
  - 单 chunk 16×16 偏移不够，**radius=16 邻域块级搜索**才稳定超过旧 2D 基线；
  - 产品流程：候选 → chunk 高度评分 → Top 块级评分 → Top-20 radius=16 邻域精修 → 最佳点 + H。
- `docs/planning/HANDOFF_2026-11-28.md`：`HeightRefiner`（H=0..24，块级群系权重、16×16 邻域；
  AfkDialog 自动重排，新增“高度 H / 有效面积 / 绝对 Y”列）；**绝对 Y = afkBaseY + H**。
- 产品代码 `src/core/HeightRefiner.*` 已实现上述“块级权重 + 粗 4 细 1 + ±16 邻域 + H=0..24”；
  本次直接复用，不再新增研究模型。

### 2.2 本次实现

- `src/core/HeightRefiner.h` 新增 `afkBaseYForVersion(javaVersionId, bedrock)`：
  Java 1.18+ / Bedrock = `-63`，Java < 1.18 = `1`；AfkDialog 与主搜索共用，避免两处口径漂移。
- 环形搜索 worker 在最终候选确定后（严格统计/筛选/截断之后）逐候选调用
  `HeightRefiner::refine(x, z, inner, outer, 16)`：
  - 得到精修中心 `(x,z)`、`H=bestHeight`、同面积高度带、有效面积、有效方块数；
  - **建议挂机坐标 = (精修 x, afkBaseY + H, 精修 z)**；
  - 候选数上限 64（避免大目标数量时高度扫描拖慢搜索；超出部分显示 `x / z`、没有 Y）。
- 明确**不改变**：结果排序（仍按原 2D 覆盖/权重）、`密度/有效格` 列的统计口径（原规划中心）。
  用户要求“只显示建议坐标”，因此不做高度感知重排、不重算严格覆盖。
- 结果表：列序改为
  `# / 建议挂机坐标 X/Y/Z / 距离 / 密度(覆盖) / 有效格·总权重(仅环形) / 定位 / 传送`
  （X、Z 两列合并为第 2 列；新增 `ResultCoordItem` 按 (x,y,z) 数值排序）。
  环形模式表头 `ui.result_afk_coord_header`；非环形窗口结果表头 `ui.result_coord_header`（X/Z）。
- “定位”与“复制传送指令”都使用建议坐标：传送命令 `/tp @s <x> <建议Y> <z>`；
  没有建议高度时退回原行为（y=64）。
- tooltip（`ui.result_afk_coord_tip`）说明：覆盖列按原规划中心统计、>64 候选只精修前 64 个。

## 3. 地图覆盖范围随建议高度变化

问题：跳转结果后地图永远画蓝环；高挂机高度下三维空心球与基岩层的交集会变成**圆盘**（内孔消失）。

计算（球壳 ∩ 基岩层，刷怪面 y = baseY）：

```text
H = 建议高度（0..24）
r_out = sqrt(R² − H²)                    （R = 环形外半径，默认 128）
r_in  = H ≥ inner ? 0 : sqrt(inner² − H²)（inner = 环形内半径，默认 24）
```

- `r_in == 0` 时只画外圆（地面覆盖为圆盘）；否则画内/外双圆（环带）；
- 绿色史莱姆区块高亮同步使用该地面范围（区块与圆环/圆盘的相交判定）；
- 候选带高度时标签显示 `Y=…（H=…）地面环带 r=…~…` / `地面圆盘 r≤…`；
- 跳转时缩放 span 按 `r_out`（而不是固定 128）自适应；状态栏给出建议坐标 (x, y, z)；
- 没有高度信息（非环形/超出精修上限）时回退原来的 24~128 环画法。

## 4. 环形搜索进度（顶部进度行 + 底部“进度”流水）

问题：普通搜索/构建有进度流水与阶段/已用时，但环形搜索走独立后台任务，完全没接：
底部「进度」页永远空白，只有「反馈」页有内容。

实现：
- `RingSearchResult::phase`（worker 写、GUI 只读）：
  `0 准备 / 1 预筛 / 2 基线精修 / 3 k3 上界复核 / 4 严格统计 / 5 建议挂机坐标 / 6 完成`；
- `runRingSearch()`：记录 `m_searchStartMs`，启动已用时定时器（200ms）与进度流水定时器（500ms），
  顶部阶段/已用时/预计剩余（`--:--`）初始化；
- `appendProgressStreamLine()`：环形分支每 0.5 秒追加
  `[HH:MM:SS] 环形 · <阶段> · 已用时 <秒>`；
- `updateElapsedUi()`：环形分支刷新阶段文字与已用时；
- `finishRingSearch()`：停表、追加完成汇总行
  `[…] 环形完成：候选 N 个，用时 X 秒，预筛=GPU/缓存位图/快速抽样[，k3 过滤后 M]`
  （取消则为 `环形已取消（已用时 X 秒）`），阶段置“完成”，进度 100%。

## 6. 已知边界

- 建议坐标与地图覆盖只对**环形（挂机点）结果**有意义；图案/密度窗口结果显示窗口中心 (X/Z)。
- `>64` 个候选时只有前 64 个有建议 Y（tooltip 已说明）；如需全部精修需评估耗时。
- 高度模型假设平台=基岩底层、刷怪面与平台同层；不适用于自建多层平台等特殊农场。
- 建议坐标基于块级群系权重与 ±16 邻域，属于候选级结果，不宣称全局最优。
