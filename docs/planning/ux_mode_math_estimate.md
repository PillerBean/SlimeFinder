# UI 模式与纯数学预估规划

日期：2026-11-19  
目标：先优化使用体验，不改变搜索算法。

## 一、先澄清两个“预估”

当前代码里有两个不同东西：

1. `successProbabilityText()`：二次确认框里的“成功率预测”
   - 已经使用 `pSlime=0.1`
   - 图案：二项概率
   - 密度：正态近似
   - 不是抽样，但密度用了连续性修正的正态近似

2. `SlimeEngine::estimateHits()`：高命中警告
   - 分层抽样估算命中数
   - 这是“预计命中数”，不是“成功率”

计划：

```text
成功率 → 改为精确二项分布/确定性公式
高命中警告 → 改为数学期望，不再用抽样
所有文案明确标注“理论模型”，不冒充真实世界概率
```

## 二、纯数学预估

### 密度窗口

```text
n = g²
k = ceil(minDensity × n)
p = 0.1
单窗口命中概率 P = Σ(i=k..n) C(n,i) p^i (1-p)^(n-i)
候选位置数 = (spanX - g + 1) × (spanZ - g + 1)
预计命中数 = 候选位置数 × P
至少 1 个命中概率 ≈ 1 - (1-P)^候选位置数
```

说明：

- 用精确二项尾概率，不用正态近似（g 小、阈值极端时更准）。
- 大 g 可用对数求和/递推，按 (g, threshold) 缓存。
- 窗口重叠导致“至少 1 个”仍是独立近似，文案必须写明。

### 图案

```text
单方向 P = 0.1^green × 0.9^white
锁定方向：P
不锁定方向：1 - (1-P)^4   （近似，考虑四方向）
候选位置数按图案尺寸计算
预计命中数 = 候选位置数 × P
```

当前“锁定方向乘 0.25”是相对缩放，绝对值不对；计划改为上面的正向公式。

### 目标 N 的成功概率

需要区分：

```text
P(≥1)     ：范围内至少一个命中
P(≥N)     ：范围内至少 N 个命中
```

建议 UI 同时显示：

```text
单窗口命中率
预计命中数
至少 1 个的概率
至少 N 个的概率（Poisson 尾近似，标注近似）
```

不同质量模式的 P(≥N 种质量) 更复杂，先不承诺精确值，标注“理论期望，不保证”。

## 三、模式分类

不建议直接把 25 条需求做成 25 个开关。建议 4 个一级模式 + 预设方案 + 自定义。

### A. 最近结果（密度）

```text
A1 快速最近 N（允许同质量，找够 N 即停）
A2 最近 N（允许同质量，完整扫描）
A3 不同质量最近 N（每个有效格质量取最近，凑够 N 种即停）
A4 不同质量尽量 N（同 A3，但不足 N 时扫完范围）
A5 精确最近 N（GPU 不截断，必要时回退 CPU）
A6 速度优先（大范围，允许 GPU 截断并提示）
```

### B. 最优

```text
B1 全局最优 1（忽略密度阈值，不提前停止）
B2 无损分层（与精确结果一致）
B3 估算预览（明确标注非精确）
```

### C. 环形挂机点

```text
C1 覆盖最大（允许同质量/同覆盖类型）
C2 不同覆盖类型（每种只取最优）
```

### D. 严格图案

```text
D1 单方向最近 N
D2 四方向最近 N（同位置去重）
D3 全部候选
```

### E. 自定义

```text
显示所有语义开关
```

## 四、非预设需求归属

这些不是“结果方案”，不应塞进预设下拉框：

| 需求 | 归属 |
|---|---|
| 完整缓存优先 | 加速策略（自动） |
| 部分缓存混合计算 | 加速策略（自动） |
| 构建缓存 RAM 上限 | 构建页/守卫 |
| 构建断点续传 | 构建页/分段 |
| 环形取消清结果 | 生命周期 |
| GPU 截断提示 | 结果横幅 |
| GPU 失败只补失败行 | 引擎 |
| 缓存删除/修改不崩溃 | 引擎 |
| 关闭有界退出 | 生命周期 |
| 多功能优先级 | 内部规则/文档 |

## 五、详细开关的显示规则

### 非自定义方案

只显示：

```text
模式
方案
目标数量 N
范围/起点
图案（严格模式）
环形半径（环形模式）
加速与资源（独立折叠区）
```

隐藏：

```text
算法选择
忽略阈值
提前停止
智能范围
最小密度
同质化细节
抛光/候选数等高级项
```

### 自定义方案

显示全部语义开关，并显示“可能明显降速”声明。

### 加速与资源

GPU、缓存、RAM、线程数始终独立，不属于“自定义方案”，始终可访问。

## 七、需要确认的两个冲突点

### 1. 忽略阈值的排序

当前实现：

```text
忽略阈值 = 按有效格/密度最优
```

需求截图里写：

```text
忽略阈值时，结果仍按最近 N 排序，而不是按密度排序
```

两者冲突，必须二选一：

```text
A. 密度最优（当前实现）
B. 最近 N（截图旧需求）
```

### 2. “成功率”定义

```text
A. 至少 1 个命中
B. 至少 N 个命中
C. 两者都显示（推荐）
```
