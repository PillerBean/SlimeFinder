## 四、新算法方向

### 候选核：环形加权区块卷积

对每个区块不只用 0/1，而是计算它与环带的重叠权重：

```text
chunkWeight =
  该 16×16 区块与 outer 环带的重叠面积
  - 与 inner 禁区的重叠面积
```

候选评分：

```text
score(center) =
  Σ slimeChunk(cx,cz) × chunkWeight(cx-centerX, cz-centerZ)
```

流程：

```text
GPU：区块级加权卷积，输出 Top-K
CPU/GPU：对 Top-K 的 16×16 子偏移做精确环形评分
```

### 为什么它可能更好

```text
目标本身就是环形加权覆盖
方形区块数量只是环形的代理指标
加权卷积更接近目标，候选集更可能有高质量点
```

### 为什么它可能更快

```text
区块级卷积比逐方块精确评分便宜
全图只做一次粗评分
精确评分只对 Top-K 做
```

## 五、阶段目标

### P0：建立离线评测体系

必须先做，避免每次全图实战。

```text
固定 3–5 个种子：
  社区种子 -8180004378910677489
  旧种子 0
  2–3 个随机种子

固定指标：
  Top-K 候选召回
  最好 coveredWeight / coveredBlocks
  候选生成时间
  精修时间
  总时间
  内存峰值
  崩溃率
```

产出：

```text
benchmark 种子表
已知参考点
候选池（缓存一次全图候选，后续离线重排）
评测脚本
```

验收：

```text
任意新候选核先离线比较
只有离线指标不劣于方形的方案，才允许跑全图
```

### P1：环形加权候选核原型

```text
先 CPU 小区域验证权重/召回
再做 GPU 全图版本
输出 Top-K，不直接精确扫全图
```

验收：

```text
在 P0 候选池上，Top-K 召回不低于方形
候选生成时间不超过 210s
不出现 GPU 崩溃
```

### P2：全图质量确认

只对 P1 赢家跑全图。

验收至少满足一项：

```text
A. ≤210s 复现 14739 / 14595.893
B. ≤20min 超过 14739
C. 同质量下总时间明显低于 210s
```

如果三项都做不到：

```text
判定当前目标已接近该问题在该候选核下的实际上限
停止质量军备竞赛，转回产品体验
```

### P3：产品化

只有 P2 达标才进入产品：

```text
新增候选核作为预设/高级选项
不回归 3.13.10 已有预设和纯数学预测
记录基准与来源
```

## 几何修正（2026-11-21）

实测目标环带是**圆盘环**：

```text
inner² <= dx² + dz² <= outer²
```

不是方窗减内窗。P1 的 chunkWeight 必须用「16×16 区块矩形与圆盘环的交叠面积」，
不能简单用外方窗计数减内方窗计数。

这也解释了之前用 3×3/内方窗做 ringRank 的效果有限：代理几何与目标几何不一致。
