## 4. 关键约束与设计决定（新增/保留）

- 2D 方形 GPU 预筛不要因不精确移除；**预筛来源按实测选择**：GPU 优先、缓存预筛兜底
  （若有 AVX2 优化让 CPU 位图预筛稳定快于 GPU，再评估改为缓存优先，见 k3 文档 §7）。
- k3 是候选级上界复核，不宣称全局最优；GPU/缓存两条路径在 `topPerBand` 边界 count 平局上
  取舍不同（GPU 本身未定义、同输入多次运行种子数不稳定），k3 最终最优候选一致。
- H>24 由 H=24 支配；高度只扫 0..24。
- Bedrock 1.18+ 有上游哈希校验；1.18 前 Bedrock 分层生成器与 Java 哈希不适用。
- 公共标识符用下划线，不用点；不伪造库中不存在的版本 1.3/1.15。
- 环形内外半径现在只在搜索页 ③ 结果要求里出现（设置页已移除，`settings.ringInner/ringOuter` 字段保留）。
- **搜索页顺序**：先「搜索内容」后「搜索方式」——搜索方式的候选池由模式/形状决定，不能反过来。
- **建议挂机坐标**：计算依据 = 研究文档的球壳模型 + 块级权重 + ±16 邻域 + H=0..24（H>24 由 24 支配）；
  `绝对 Y = afkBaseY + H`。按用户要求“只显示”，不改结果排序/中心统计口径；候选上限 64。
- **地图地面覆盖**：按 `r_out/r_in` 公式画交点，H≥内半径时是圆盘；不要把“环”写死。
- **群系折算系数（2026-11-29 复核）**：Java 用精确分数（最高档 100/515），折算 = 本群系分数÷100/515，
  即用户表格的 515/615（河流）、515/540（巨型针叶林含丘陵）、515/610（溶洞）、蘑菇岛/深暗之地=0；
  硫磺洞穴（26.2+）= 25/315÷100/515 ≈ 0.4087（普通史莱姆；硫方怪不掉黏液球，不污染农场）。
  基岩版：英文 Wiki 各群系名义 100/1，但**河流/冻河实际不刷**（无 monster 生成类别；中文 Wiki +
  Mojira MCPE-161245 确认）⇒ 0；其它语言 Wiki 未找到该条例外。当前计算仍只对 Java 启用群系加权。
- **发布**：任何 Release / 安装包上传 / tag 都必须先经用户明确批准；代码提交与推送可以继续。

## 8. 已知风险

- **开发速度规定**：测试版迭代默认只跑 `scripts\qa\check_fast.ps1`（构建+单测+三语+部署同步）；
  GUI 自检/参考对拍/打包验证只在发布前或大改动后跑。不要把“全量门禁”当成每轮必跑。
- **部署目录必须最新**：`dist\SlimeFinder\SlimeFinder.exe` 是用户手工检验路径；每轮构建后跑
  `scripts\release\sync_local_deploy.ps1`。若 exe 正在运行会被改名替换，需重启程序才生效。
- 搜索页嵌套分组在窄栏多一层固定宽度开销（左栏最小宽 zh 360→370）；再嵌层要重新核横滚动。
- 自检对 GUI 布局/文案耦合较深：改按钮文案/分组标题要同步 SelfTest 断言与三语 key。
- GUI 自检需独占运行（并发跑会让 GPU/原生 OpenCL 偶发崩溃）；干净 build 首次跑前需预置 config。
- 建议挂机坐标会增加环形搜索耗时：单候选块级 ±16 邻域约 15–50 ms（Java 加权），上限 64 候选；
  若将来目标数量很大，需要评估是否按需计算（例如只对当前可见/选中行计算）。
