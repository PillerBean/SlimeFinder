# 设置面板「分级展开 + GPU 设置入口」排序规划（3.10.9 预备）

> 目标：① 加「自定义方案可能导致速度降低」声明；② 高级开关只在方案=自定义后展开；
> ③ GPU 开关旁加入口，展开 GPU 相关设置（流式等）。
> 原则：**先规划顺序、再动手**；一次做完、少返工；不改算法，只改 UI 与状态联动。

## 一、开关分级（哪些常显 / 哪些只在自定义后出现 / 哪些放进 GPU 展开）

| 级别 | 内容 | 理由 |
|---|---|---|
| **基础（常显）** | 平台/种子/游戏版本（顶部栏）、搜索范围（半径/预设/起点）、搜索模式、方案下拉、目标数量、图案网格（图案模式） | 不选就没法搜索 |
| **自定义才显示的「结果要求」** | 找够即停、由近及远（智能范围）、最小密度、忽略阈值 | 预设已经替你选好；乱调会改变结果或拖慢速度 |
| **自定义才显示的「匹配方式」** | 搜索算法四选一 + 分层级别/阈值比例、采样间隔/精算采样 | 同上；「保守模式（纯暴力）」会让速度差 100 倍 |
| **GPU 主开关 + 展开（新增入口）** | 主开关常显；点「设置 ▸」展开：状态/设备信息、图案 GPU 流式、GPU 占用率上限、启动时自动检测、实测吞吐率/重新检测 | GPU 相关项集中，不挤占左列；默认收起防误调 |
| **性能与资源（常显，但独立）** | 线程数、内存上限（MB）、CPU 占用率上限 | 影响速度不影响结果，给需要的人 |
| **缓存管理（常显）** | 缓存开关/加载/清除/构建页入口 | 现有分组不动 |

## 二、左列最终纵向顺序（从上到下）

```
① 搜索范围    半径(区块) / 快速预设(附近·局部·全局·Java边界·基岩边界) / 查询起点 / 方块↔区块
② 搜索模式    图案搜索 / 密度搜索
③ 方案        [方案 ▾]  ← 预设列表（随模式 3~4 种或 2 种 + 自定义）
               └ 提示行：当前方案说明；当方案=自定义时，追加琥珀色声明行：
                  “⚠ 自定义方案的开关组合可能明显降低搜索速度；不确定时请先选上面的方案预设。”
④ 结果要求    目标数量（常显）
               └［仅自定义］找够即停 / 由近及远 / 最小密度 / 忽略阈值
⑤ 匹配方式    ［仅自定义］搜索算法 + 分层级别/阈值比例 + 采样间隔/精算采样
⑥ 图案网格    ［仅图案模式］网格、方向锁定、行/列/应用/全部忽略
⑦ GPU 加速    [☑ GPU 加速]   [设置 ▸]  ← 齿轮/箭头按钮，展开面板（默认收起，状态记忆）
               └ 展开内容顺序：
                  1) 状态行：GPU 未检测/可用·设备名·显存·CU
                  2) 图案 GPU 流式（默认关）
                  3) GPU 占用率上限（10~100%）
                  4) 启动时自动检测 GPU（默认关）
                  5) 实测吞吐率行 + [重新检测] 按钮
⑧ 性能与资源  线程数 / 内存上限 / CPU 占用率上限（放在最底部，保持现状只调整组内顺序）
⑨ 缓存管理    缓存开关 / 加载 / 清除 / 构建入口（不动）
```

排序理由：
- 「方案」必须紧跟「搜索模式」（模式决定方案数量），并位于它会影响的所有开关**之前**；
- 「目标数量」属于基本需求，常显；其余结果要求收进自定义；
- 算法属于"影响结果也影响速度"的危险区，收进自定义；
- GPU 全部相关项聚成一组，主开关常显（常用）、细节展开（少用且易误调）；
- 线程/内存/CPU 上限放最后：只影响速度，不影响结果。

## 三、声明文案与显示规则

- 中文：`⚠ 自定义方案由你自己组合开关，某些组合可能明显降低搜索速度（例如算法选「保守模式」、最小密度设为 0）。不确定时请先选上面的方案预设。`
- 英文：`⚠ Custom schemes combine switches yourself; some combinations can be much slower (e.g. the brute-force algorithm or a minimum density of 0). Pick a preset above if unsure.`
- 显示位置：方案下拉正下方的一行（11px、琥珀色）；**仅方案=自定义时显示**，选预设时隐藏；
- 首次切到自定义（本次运行内第一次）时，额外在反馈栏记一条 info，不弹模态框（避免打断）；
- 同时写入 3.10.9 更新历史。

## 四、展开/收起与状态联动规则

| 规则 | 说明 |
|---|---|
| 方案→自定义 | 展开 ④⑤ 全部；方案→预设 | 收起 ④⑤（保留值），并在提示行显示该预设做了什么 |
| 手改 ④⑤ 任一控件 | 自动切到自定义（沿用现有 markPresetCustom）+ 显示声明 |
| 图案/密度切换 | 重建预设列表（现有逻辑不动）；④⑤ 内容按模式调整（图案模式无阈值/算法） |
| GPU 展开按钮 | 点击切换展开/收起；展开状态记入内存（不写 config），图标 ▸/▾ |
| GPU 流式 | 与设置页「高级 → 图案 GPU 流式」**双向同步**（true 单一数据源 m_settings.gpuPatternStream） |
| 窄列 | 展开面板纵向排列，不增加左列最小宽度；滚动区照常 |
| 还原默认布局 | 恢复"高级项收起、GPU 展开收起状态"默认 |
| 自检模式 | 不受展开状态影响：断言前先确保所需控件已展开（或控件直接可访问） |

## 五、自检断言行（新增/调整）

1. 方案=预设 时：④⑤ 的控件 **不可见**；方案=自定义 时全部可见。
2. 方案=自定义 时：声明行可见且包含「速度」；方案=预设时声明行不可见。
3. 手改「找够即停/算法/阈值/忽略阈值」→ 方案自动变「自定义」且声明出现（现有行为加固）。
4. GPU「设置 ▸」：初始收起；点击后展开，内部顺序 = 状态行→图案流式→占用率→自动检测→吞吐率/重新检测。
5. GPU 流式勾选与设置页复选框一致（改一处另一处跟随，config 落盘）。
6. 切换到「其它页（缓存构建/设置/更新历史）再回搜索页」：展开状态返回默认收起、方案保持、控件值不丢。
7. 三纵列宽度不变（左/中/右 380/480/360 默认），最小窗口 1000×650 无横向滚动条。
8. 性能基线 `perf_baseline --check` 通过（纯 UI 改动，引擎零改动）。

## 六、实现步骤（一次做完的落地顺序）

| 步 | 内容 | 验收 |
|---|---|---|
| S1 | 方案下拉下方加声明行（新 QLabel，objectName=presetDisclaimer），接 applySelectedPreset/applyResultConflicts | 预设/自定义切换显示正确；自检 2 过 |
| S2 | 把 ④（找够即停/由近及远/最小密度/忽略阈值）从常显改为自定义容器（QWidget 包 4 行），预设时 setVisible(false) | 自检 1/3 过；预设用户界面更干净 |
| S3 | 把 ⑤（算法 + 分层/采样参数）包进自定义容器，联动 updateAlgorithmPanels 可见性 | 自检 1 过；算法改动仍触发自定义 |
| S4 | 「目标数量」留在 ④ 常显；GPU 组重构：主开关 + 「设置 ▸」按钮 + 展开面板（状态/流式/占用率/自动检测/吞吐率） | 自检 4/5 过 |
| S5 | 流式/占用率/自动检测与 AppSettings 双向同步 + config 落盘；删掉设置页重复入口或标注「同搜索页 GPU 设置」 | 自检 5 过；config round-trip 过 |
| S6 | 更新历史 + 文档 + 版本号；GUI 自检 3 轮 + 打包 | 3 轮 0 FAIL；包通过 |

**风险与回滚**：只改 UI 可见性与同步，不碰 SearchOptions 构建；若自检失败或布局错乱，回滚方式 = 恢复三处 setVisible 逻辑 + 删展开面板（不涉及引擎）。

## 七、待确认（默认方案）

- Q1 自定义专属范围：默认 ④⑤ 全部（停止方式/阈值/忽略阈值/算法/分层/采样）。若想更宽松，可只收 ⑤（算法）而 ④ 常显。
- Q2 GPU 入口形态：默认「设置 ▸ 内嵌折叠面板」（不用弹窗，便于触控与自检）；若想弹窗可改。
- Q3 声明强度：默认「琥珀色提示行 + 首次切换记一条反馈」，不弹窗。
