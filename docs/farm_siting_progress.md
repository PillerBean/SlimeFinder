## ① 环形算法（1/16 区块精度）✅ 已完成

### 要解决的问题

史莱姆农场要「站对位置」：玩家附近 **R 格**（生物生成半径，默认 128）内的史莱姆区块面积越大，
可刷怪格数越多。史莱姆区块是 16×16，**最优站位经常落在区块角点上**（同时覆盖 4 个区块）——
只按区块中心给建议会漏掉更优解，所以精度必须细到 **1 格 = 1/16 区块**。

### 实现

新增核心模块 `src/core/AfkPlanner.{h,cpp}`（与 Qt 无关，带单元测试）：

| 步骤 | 做法 |
|---|---|
| 占用图 | 候选窗口内按 1 格铺出史莱姆区块（每区块 16×16 = 256 格） |
| 前缀和 | 二维积分图（int32），任意矩形 O(1) 求和 |
| 圆内求和 | 对每一行 `dz∈[-R,R]` 用圆方程算半宽 `w=⌊√(R²−dz²)⌋`，一次 rowSum ⇒ 每候选 **O(R)** |
| 提速 | 先按 4 格步长粗扫，再对候选点 ±4 格内**按 1 格精修** ⇒ 结果仍是 1/16 区块精度 |
| 打平取点 | 覆盖面积最大是一个「平台」：取平台**几何重心**附近的点 ⇒ 2×2 区块阵自然给出四区块公共角点 (16,16)，与社区「站在四个史莱姆区块交角挂机」的经验一致；同时对同一最大值给出唯一、可解释的答案 |
| 多候选 | 精修阶段用「最小间距」做非极大值抑制，给出**互相分散**的多个可选点（默认 5 个，间距 24 格） |

对外接口（`slime::AfkPlanner`）：`plan()` / `planForSeed()`（按版本+种子）/ `evaluate()`（单点评估）/
`planBruteForce()`（测试对照）/ `slimeBlocksInArea()`。
每个候选点带：方块坐标、覆盖格数、覆盖区块数、覆盖率、是否区块角点、覆盖区块重心、到重心距离。

### 界面

### 已知取舍

- 覆盖面积按「史莱姆区块的 16×16 水平格数」计，**不含 Y 轴与光照/空间条件**（Java 里史莱姆只在 y<40 刷），
  因此它是「刷怪潜力的上界」，用于比较位置优劣是有效的；具体挂机高度仍要看地形。
- 覆盖率 = 覆盖格数 / πR²，是该圆内史莱姆面积占比，不是游戏内实际生成成功率。
- 超大范围（>64×64 区块）会在中心收窄，摘要里明确写出，不静默截断。

## ② 地图预览（彩色群系，chunkbase 风格）✅ 已完成

### 目标（用户补充要求）

要像 chunkbase / minecraftsearch 的种子地图那样**彩色预览**：一眼看出是海洋、森林、沙漠还是雪原，

### 关键实现细节（踩过的坑）

1. **cubiomes 的坐标语义**：`Range` / `getBiomeAt()` 的 x/z 是**缩放后坐标**（scale=4 时传 biome 坐标 = 方块/4），
   y 在 scale>1 时也是 1:4 —— 一开始按方块坐标传，颜色会整体错位；已在 `BiomeMap` 内统一换算并加单元测试。
2. **性能**：逐点 `getBiomeAt()` 每次都要分配缓存，太慢；改为按可见范围调用 `genArea()` 一次成型，
   并把结果缓存为 QImage（视图/精度/版本不变时直接复用，拖动/重绘不重算）。
3. **基岩版**：cubiomes 不提供基岩版群系 ⇒ 地图对基岩版只画史莱姆区块与网格，摘要里明确写「群系：不可用（基岩版）」，不假装有数据。

## ③ 权重算法（群系刷怪效率）✅ 已完成

### 做法

新增 `src/core/SpawnWeights.{h,cpp}`：**群系 id → 刷怪效率权重**（0 = 完全不刷，1 = 表内最高档），
并让 `AfkPlanner` 支持**加权覆盖**排序：

| 部分 | 说明 |
|---|---|
| 权重表 | 按 Minecraft Wiki 的「史莱姆生成权重表」录入 60+ 群系的 Java 生成占比，以最高档 **19.42%** 归一化为 1.0 |
| 典型值 | 竹林/森林/平原周边 **1.0**；沼泽 **0.998 + 地表加成**；海洋 **0.99**；河流 **0.837**；溶洞 **0.844**；蘑菇岛 / 深暗域 **0** |
| 基岩版 | 各群系 slime 权重恒为 100（组队规模 1）⇒ 统一 1.0；**但河流/冻河在基岩版不生成**（见下） |
| 加权规划 | `AfkPlanOptions::weightAt`（方块 → 权重回调）：加权模式下额外维护一张「千分比」前缀和，圆内求和得到 **加权覆盖**；排序按加权值，同时仍报告原始格数与平均权重 |
| 界面 | 挂机点对话框新增「平台（Java/基岩）」与「群系版本」下拉；表格新增**加权覆盖**与**平均权重**两列；摘要写明当前加权模式 |
