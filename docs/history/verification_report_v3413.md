## 三、套任务书第四节预警的「连锁反应」——全部命中并已解决

1. **缓存读写竞态（崩溃）**：块数 2→47 后，工作线程的「缓存命中填充 / isSlime / covers」与归并线程的写
   （`ensureRange` 重分配向量、`m_outliers` swap）并发 ⇒ **6 次运行 2 次 0xC0000005**。
   修复：`SearchOptions::cacheReadMu`（分块路径把 `cacheMu` 交给工作线程，仅构建模式）＋ 位图行**拷贝**到
   线程本地缓冲；`covers()` 与命中段查询整段持锁。第一版「工作线程完全不读缓存」虽不崩，但改变了覆盖声明
   与条目簿记（9 条既有断言失败）⇒ 已放弃，采用语义不变版。
2. **块边界条目重复计入**：块数据域末尾 hMax-1 行属下一块锚点行域、两块都收集 ⇒ 同一点既进 outliers 又置位
   ⇒ `entryCount` 虚高且随归并顺序波动（实测 ±224）。修复：`collectSkipZ0/Z1`（尾部行只由末块收集）
   ⇒ `entryCount == 真值`，且两种几何下**条目数完全相同**。
3. **拷贝缓冲被并行线程共用**（我自己引入的）：`runImpl` 的填充在 OpenMP 线程里并行 ⇒ 命中缓存的搜索会读到
   错行（[12]/[22] 的「跳过填充后结果一致」失败）。改 `static thread_local` 后一次修好。
4. **构建模式容量上限漏报**：块变小后单块位图可能始终小于预算字节数 ⇒ 只靠 `sizeBytes()` 判定会漏
   `hitCacheBudget`；准入关闭（条目 ≈ 预算/8 字节）本是同意事件 ⇒ 构建模式下同时置 `budgetStop`。
5. **既有断言与旧几何的耦合**：[5]/[12] 断言「2 块几何 / 相邻块声明不重叠」这类分块语义，已用
   `SLIME_CHUNK_TARGET=0` 钉住原意；**新几何由 [25]/[28] 与 44G 对照台覆盖**。

## 四、新增的回归防线

- **单元组 [27] PerfLog 采样线程安全**：8 线程并发轰同一采样器 ⇒ 断言「越界 0 次 + 两口径自洽」；顺序采样忙等断言 `all≈100%`。
- **单元组 [28] 归并调度无关性**：解耦 vs 内联（同线程数）⇒ 位图**逐字一致** + isSlime/lookup 抽样一致；
  4 线程 vs 1 线程 ⇒ 语义等价（覆盖域一致 + 抽样一致；几何本就按并发而定，故不逐矩形比较）。
- **search.summary 诊断字段**：`mergeQueueWaitMax` / `mergeMode`（decoupled/inline）；`cpu.sample` 增 `cores=` / `all=`。
