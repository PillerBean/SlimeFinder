# v3.5.24 验证报告（测试版）

- 版本：v3.5.24（测试版）
- 主题：**环形异步延迟修复 · 排序网格记忆 · 设置项响应时机标注**

## 一、这一轮改了什么

| # | 内容 | 说明 |
|---|---|---|
| 1 | 环形搜索「异步化」带来的 40ms 延迟 | v3.5.22 改成后台线程 + 事件循环轮询，但轮询间隔是 40ms，界面等待被硬加了最多 40ms（自检里 0.008s 的搜索显示成 0.044s）。轮询改为 **2ms**，并且「用时」只统计**真实计算时间** |
| 2 | 排序权重网格记忆一格 | 版本+种子+范围+网格档位完全相同时直接复用上一次的权重网格，连续同类搜索省 **2~6 ms** |
| 3 | 设置页响应时机标注 | 界面语言 →「（重启后生效）」；CPU 占用率/内存上限 →「（下次搜索）」；启动时检测 GPU →「（下次启动）」 |

## 二、当前速度（`--bench-ring`，R=128 内 24，种子 12345）

| 范围 | 合计 | 粗扫 | 候选严格权重 |
|---|---|---|---|
| 400×400 区块 | **18.2 ms** | 11.1 ms | 4.7 ms |
| 1000×1000 区块 | **25.9 ms** | 19.5 ms | 4.9 ms |
| 2000×2000 区块 | **38.5 ms** | 31.9 ms | 4.4 ms |

GUI 端到端（自检实测）：0.009~0.014 s。

关于 AVX2：这轮**没有**做，原因是实测粗扫已达 ~9 G 次加法/秒，接近内存带宽上限；
理论上限提升约 1.5×，摊到整体只有 10~15%，风险（新编译单元 + 运行时分派）与收益不匹配。
下一步更划算的是**分层筛**（1/4 分辨率粗核预筛，预计整体 2×），已写在 `docs/speed_plan.md`。
