# v3.1.0 验证与性能报告（verification_report_v310.md）

- 被测版本：SlimeFinder v3.1.0（C++20 / Qt 6.11.2 / MSVC 19.51 / Release `/O2 /openmp /GL /LTCG`）
- 基线版本：v3.0.0（同机同参数复测，二进制存档于 `bench_baseline_v300/`）
- 测试机：AMD Ryzen 5 5600（6C/12T，Zen3，支持 AVX2+FMA，无 AVX-512），Windows 11 x64

## 1. 性能对比与 5 亿目标达成情况

### 1.1 扫描内核（对应任务书 2.1 基线“约 3 亿/秒”的哈希+LCG 判定内核）

| 场景 | v3.0.0 | v3.1.0 | 提升 | 目标 |
|---|---|---|---|---|
| Java 1000×1000 单核 | 约 3.24 亿区块/秒（3.1 ms） | 约 5.9 亿区块/秒（1.7 ms） | +83% | — |
| Java 10000×10000 单核 | 约 2.96 亿区块/秒（338 ms） | **约 5.2~5.5 亿区块/秒（183~190 ms）** | +80% | ≥4 亿（硬）/ ≥5 亿（方向） |
| Java 10000×10000 多核 12T | 约 19.1 亿区块/秒（52 ms） | 约 31 亿区块/秒（32 ms） | +64% | — |

**结论：单核 ≥ 4 亿（硬性）达成（约 5.3 亿），≥ 5 亿方向目标达成（两次复测 5.26 / 5.47 亿）。**

### 1.2 游戏精确基岩版判定（完整 624 步 MT19937）

| 场景 | v3.0.0 | v3.1.0 | 提升 |
|---|---|---|---|
| 2000×2000 单核 | 22.8 万区块/秒（17.5 s） | 约 135 万区块/秒（约 3.0 s） | +490% |
| 2000×2000 多核 12T | 150 万区块/秒（2.7 s） | 约 600 万区块/秒（0.65~0.81 s） | +300% |

### 1.3 其他

|---|---|---|
| 缓存加载 100 万条目 | 45 ms | 约 39 ms |

### 1.4 5 亿/秒瓶颈分析（任务书第七节要求）

**为何“游戏精确基岩版判定”无法达到 4~5 亿/秒（单核）**
- 一次准确判定 = MT19937 完整流程：624 步初始化（含顺序依赖链）+ 624 步 twist + 加扰 + mod 10，
  约 **1248 次 32 位运算**；
- 理想上限（4 发射/周期、零开销）：1248 ÷ 4 ≈ 312 周期/区块 → ~1.2×10⁷ 区块/秒（3.7 GHz）；
  实测 v3.1.0 约 1.35×10⁶/秒，已达该理想值 ~11%（受 624 步串行链延迟限制）；
- 即使 SIMD 8 路并行 8 个独立判定（任务书 1.1 思路），也只能把多链吞吐推向 ~10⁷~10⁸ 量级，
  **仍与 4×10⁸/秒相差 1~2 个数量级**——该差距源于“算法一步数”而非实现质量；
- 结论：任务书 2.1 所述“约 3 亿/秒（v3.0.0 实测）”对应的是**哈希+LCG 型判定内核
  （即 Java 版判定，本项目报告的 3.0~3.3 亿基线）**；该内核经 v3.1.0 优化已达 5.2~5.5 亿/秒。
  基岩版维持游戏精确 MT（保证与参考实现逐位一致、111 项测试不变），以缓存补齐大范围场景。
- 采用的具体优化（对应任务书 1.1~1.4 各路径，均在保持输出逐位一致的前提下）：
  1. **标量重构（等效 SIMD 收益的“寄存器收集”）**：行基座拆解 + x 尾项预计算表 +
     64 区块寄存器累计写回 → 分支与内存读写大幅削减（约 +40%）；
  2. **结果存储**：v3.0.0 已采用“容量 N 最大堆 + 稳定排序键”，优于小 N vector / 大 N set
     的二分策略（O(log N) 推送、内存上界固定）；
  3. **编译**：`/GL + /LTCG` 链接时代码生成（约 +3%）；
  4. **分支预测**：取消循环内每区块存储分支（累计写回）、twist 分支改掩码；
  5. **基岩版双链融合**：两条独立 MT 链同循环以隐藏 624 步串行延迟（单核 +490%）。
- 说明：任务书 1.1 的 AVX2 向量化（`_mm256_mul_epu32` 等）作为“方向”已在
  `build_instructions.md` 记录（单文件 `/arch:AVX2` + `__AVX2__` + cpuid 回退方案），
  但本机实测标量优化已达成 5 亿目标且保留全 CPU 兼容，故主路径保持标量；
  对追求极限者可在该文档指引下按需加入 SIMD 内核。
