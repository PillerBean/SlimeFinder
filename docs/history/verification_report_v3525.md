# v3.5.25 验证报告（测试版）— 提速 A / B / C 的实测结论

- 版本：v3.5.25（测试版）
- 结论一句话：**A 落地并生效（400×400 17.6→14.4 ms），B 的方案被实测证伪、C 被实测否决并回退**。

## 一、A：精修阶段重写（已落地，结果逐位一致）

拆成三件事：

| 改动 | 说明 |
|---|---|
| 窗口稀疏表 | 每个候选的 17×17 窗口只保留史莱姆格（~29 个），内层去掉两个分支 |
| 子偏移核转置布局 | `subK[(sz*16+sx)][dj][di]` → `subKT[dj][di][256]`，一个史莱姆格的 256 个亚格计数变成**连续 512 B**；单候选核访存 148 KB → ~15 KB |
| 从窗口直接统计覆盖 | 原来每个候选还要 `countChunksInAnnulus()` 再跑 289 次间接谓词（120 个候选 ≈ 3.5 万次），现在直接用窗口里的占用信息算区块数与重心 |

`[校验] 内核精修 vs 逐格统计：完全一致` —— 所有档位都逐位一致，零质量损失。

实测（min/median of 5，ms）：

| 范围 | 改前 | 改后 |
|---|---|---|
| 400×400 区块 | 17.6 | **14.4 / 14.6** |
| 1000×1000 区块 | 25.0 | **23.7 / 24.4** |
| 2000×2000 区块 | 38.5 | **36.2 / 38.6** |

## 二、B：分层筛 —— 实测证伪

原假设：粗筛能省掉大部分候选。**错**。这个算法里粗扫是「按史莱姆区块散射核」，
代价 = 史莱姆区块数 × 核系数（289），**与候选点数量无关**——先用粗核筛一遍不会少散射任何一格。
真正能降粗扫成本的是：把 `int32` 累加换成 `int16`（无权重首轮，最大 289 < 32767，访存减半）、
或按「核权重分区」只处理非零核行。这两条会改变排序口径（需重新校验质量），本轮未做。

## 三、C：严格统计共享采样 —— 已实现、实测否决、已回退

把「每候选×每行带各建一份群系权重网格」改成「每候选一份」，采样格数 **5149 → 999（-81%）**，
但墙钟时间没降（5.0 → 5.8 ms）：并行任务数从 32 掉到 8，在 4 物理核上出现尾延迟，
采样省下的时间被负载不均吃掉。已回退到按行带并行的版本。

## 四、与物理极限的差距（400×400 区块）

按访存/带宽与采样成本的**下界**估算（不含调度开销）：

| 阶段 | 现在 | 下界估算 | 差距 | 下界依据 |
|---|---|---|---|---|
| 粗扫散射 | 5.5~6.6 ms | ~1.1 ms | **5×** | 19k 史莱姆区块 × 289 次 int32 RMW ≈ 22 MB，按 20 GB/s 带宽 |
| 精修+抛光 | 6.8~7.4 ms | ~0.4 ms | **~18×** | 48 候选 × 148 KB 核流 ≈ 7 MB + 37 万次算术 |
| 严格 1:4 统计 | 4.5~5.3 ms | ~1.3 ms | **3.5×** | 5.1k 次群系采样 × 0.9 µs ÷ 4 线程 + 40 万格环带扫描 |
| 排序网格 | 1.9~2.5 ms | ~0.5 ms | **4×** | ~600 次群系采样 |
| **合计** | **14.4 ms** | **≈3.3 ms** | **≈4.4×** | |

**读法**：整体离"带宽/采样成本下界"还有约 4.4 倍；但每一档的"下界"都是理想并行、零调度、零间接调用。
现实可达区间估计 **8~9 ms**（1.6×），需要：
1. 精修的 OpenMP 尾延迟（8 个候选 4 核 → 两波）改成细粒度任务；
2. 粗扫 `int16` 首轮 + `int32` 复核；
3. 群系采样批量化（`genArea` 条带一次性取）。
