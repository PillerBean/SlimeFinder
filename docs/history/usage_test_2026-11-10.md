## 2. 全图取消（真实等待 5 秒后点取消）

| 场景 | 取消请求时刻 | 取消到退出 | 用时 | 结果 | 内存峰值 |
|---|---|---|---|---|---|
| GPU 全图 | 5.008 s | **96 ms** | 5.104 s | cancelled=1 | 1123 MB |
| CPU 全图 | 5.012 s | **42 ms** | 5.054 s | cancelled=1 | 1573 MB |

结论：取消响应在 **<100 ms** 级别；取消时 `scanned` 统计为 0（引擎取消路径不汇总），
但进程/线程能立即退出，无卡死。

## 3. 环形「快速」全图

| 场景 | 结果 | 用时 | 最优覆盖率 | 内存峰值 |
|---|---|---|---|---|
| CPU 全图抽样 | 5 | **98 ms** | 22.2% | 7 MB |
| GPU 全图抽样 | 5 | **98.6 ms** | 22.2% | 85 MB |
| CPU 2k² 精确 | 5 | 102 ms | 21.4% | 198 MB |

- 全图抽样样本约 40 万（粗扫步长 ≈5934 区块），耗时约 0.1 s；修复前规划器 4e12 上限会让整图**静默返回 0**。
- **环带覆盖率最高约 22%**：最小密度默认 0.3 时全图仍会是 0 结果；
  已改为「切到环形时自动把最小密度暂降为 0，切回正方形恢复原值」，用户可手动调高。
- 环形快速 2k/10k/30k 抽样：31 ms / 89 ms / 86 ms；GPU 与 CPU 基本同速（计算主要在 CPU 规划器）。
- 环形精确 2k²：102 ms（界面限制精确模式 ≤400 万区块）。

## 5. 本轮发现的真实问题

1. **环形全图 0 结果**：规划器物理上限 4e12 < Java 整图 1.406e13，静默返回空；
   已修到 1.6e13，并按实际抽样点数统计扫描量（避免 1595 万亿/秒假速度）。
2. **环形默认阈值不可达**：环带覆盖率最高 ~22%，默认最小密度 0.3 ⇒ 全图必为 0；
   已改为切换环形时暂降为 0（切回正方形恢复）。
3. **密度设置找不到**：最小密度/忽略阈值原在「结果要求」里，选预设后整组隐藏；
   已移到密度面板常显，修改自动切自定义方案。
4. **忽略阈值功能本身正常**（高阈值 .9 时普通模式 0 结果、忽略阈值模式 20 结果），
   之前主要是被隐藏/不易观察。
