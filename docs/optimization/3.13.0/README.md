## 优先候选

### 1. GPU 图案流式匹配产品化

现状：

- `SlimeEngine` 内有 GPU 图案流式匹配路径；
- 仅由环境变量 `SLIME_GPU_PATTERN=1` 开启；
- 仅单变体（方向锁定）安全；
- UI 已有 `gpuPatternStream` 设置项，但引擎未把它接入。

待查目的：

- 为什么只允许方向锁定？
  - 历史记录：4 个旋转变体分别流式匹配 + 去重，GPU 比 CPU 慢，已回退；
- 为什么用环境变量而不是设置？
  - 实验阶段未产品化；
- 必须保持：
  - 结果逐项一致；
  - 非方向锁定回退 CPU；
  - GPU 不可用回退 CPU；
  - 缓存/构建模式不启用。

### 2. 密度匹配 CPU 热点

现状：Java 密度匹配占 78%。

待查：

- 当前是否为 O(1) 滑动窗口；
- 结果收集/TopN 在 match 阶段占比；
- 历史 E3 滑窗访存优化为何未达标。

### 3. Bedrock 判定

现状：Bedrock 判定占主导，匹配占比低。

待查：

- CPU FastMt 是否接近上限；
- GPU 打包字路径是否还有引擎级开销；
- 匹配优化对 Bedrock 总耗时收益很小，优先级低于 GPU 图案。

### GPU 图案默认化细节

- 默认值：`AppSettings::gpuPatternStream = true`；
- 引擎侧只对 AMD / gfx 设备走 GPU 图案流式；
- NVIDIA / Intel 保持 CPU 路径（未验证，避免回归）；
- 旋转变体仍走 CPU（历史实测 GPU 更慢）；
- 缓存构建模式、GPU 不可用、方向未锁定均自动回退 CPU；
- 设置项仍可手动关闭。
