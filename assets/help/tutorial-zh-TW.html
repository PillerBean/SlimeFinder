史萊姆區塊查詢器 · 使用教程

這一頁寫給第一次使用的朋友：不用懂任何演算法，按順序讀一遍就能自己找到史萊姆區塊。 如果只想馬上動手，直接看【怎麼用】的五步，然後照著點就行。

【這是什麼】

這是一個幫你找到史萊姆區塊的小工具。史萊姆區塊是遊戲裡能刷史萊姆的地方，找到它們就能建農場。

先說清楚兩個詞：

  • 區塊：遊戲把你的世界切成一塊一塊來管理，每一塊是 16×16 格（水平方向）。 出生點附近那一塊就是座標 (0, 0) 的區塊。
  • 史萊姆區塊：在這些區塊的地下（Y = 40 以下，也就是 Y ≤ 39）史萊姆就能自然刷出， 和亮度沒有關係（火把、亮度多少都不影響）。平均每 10 個區塊裡大約有 1 個是史萊姆區塊 （約 10%）。

需要說明的幾點（按 Minecraft Wiki「史萊姆」條目）：

  • 高度：史萊姆區塊只在 Y = 40 以下生成史萊姆，Y ≥ 40 不會刷。
  • 亮度：史萊姆區塊不受亮度限制，插滿火把照樣刷。
  • 另一種來源：在沼澤 / 紅樹林沼澤生物群系裡，史萊姆還能在 Y=51~69 且 亮度 ≤ 7 的地方生成，滿月時機率最高。這跟「史萊姆區塊」是兩回事，本工具只算史萊姆區塊。
  • 不生成的地方：蘑菇島、深暗之域（基岩版還有河流）不會生成史萊姆。

為什麼要在意它？因為只要在一個史萊姆區塊裡挖一個刷怪房（挖到 Y=40 以下），史萊姆就會源源不斷掉下來， 黏液球、黏液塊就有了穩定來源。這也是很多人做紅石機器、做飛行器時的剛需材料。

還有一個關鍵區別：Java 版的史萊姆區塊由世界種子和區塊座標一起決定（同一個種子每次開都一樣）， 所以必須知道種子才能算；基岩版的判定演算法與 Java 版不同，而且與世界種子無關—— 每個世界的史萊姆區塊分佈都一樣，所以本工具在基岩版下不需要你填種子。

【怎麼用】

第一步：選擇遊戲版本（Java版 / 基岩版）
先在最上面的「遊戲版本」裡選你正在玩的那個。選錯版本算出來的位置完全不同，這一步最要緊。

第二步：輸入種子（Java版需要，基岩版不需要）
Java 版請把世界種子填進「世界種子」輸入框，支援負數（很長的一串數字也可以直接貼上）。 種子可以在建立世界時的種子欄看到，也可以在遊戲裡用聊天指令 /seed 檢視 （單人遊戲需要先開啟“允許作弊”）。基岩版這一步可以直接跳過。

第三步：選擇搜尋範圍（點「附近/區域性/全域性」按鈕即可）
「附近」＝以起點為中心 ±1000 區塊，「區域性」＝±5000 區塊，「全域性」＝±30000 區塊。 點一下就自動填好範圍，也可以自己手動改數字。範圍越大結果越多、耗時越長， 第一次使用建議先點「附近」試一下。

第四步：選擇搜尋模式（推薦「精確模式」）
日常直接用預設的「精確模式」，它給出的結果是 100% 完整的，不會漏。 其餘三種模式的區別見下面【四種模式怎麼選】，不確定就保持精確模式。

第五步：點選「開始搜尋」，等待結果
點下按鈕後進度條會走動，搜尋在後臺進行，介面不會卡住。 完成後右側的結果列表會顯示找到的區塊，每條都寫著距離（離你設定的起點有多遠，按由近到遠排列）， 看距離就能判斷“這個區塊跑過去要多久”。點結果卡片可以複製座標， 直接粘到記事本或聊天框裡都行。

小結一下順序：版本 → 種子 → 範圍 → 模式 → 開始搜尋。以後熟悉了，通常三步就能出結果。

【圖案怎麼畫】

「圖案編輯器」用來告訴程式：你到底想要什麼樣的史萊姆區塊分佈。 它是一張方格紙，每個格子代表一個區塊，左鍵點選格子切換顏色，三個顏色迴圈： 灰 → 白 → 綠 → 灰。每個顏色的意思如下：

  • 灰色 = 不在意（隨便是不是史萊姆區塊，程式不管這個格子）；
  • 白色 = 必須是普通區塊（即“這裡不是史萊姆區塊”）；
  • 綠色 = 必須是史萊姆區塊。

所以畫圖案的思路就是：把你在意的格子塗成白色或綠色，不在意的格子留成灰色。 灰色留得越多，程式要滿足的條件越少，結果自然也越多、搜得越快。

舉個例子：你想找「苦力怕形狀」就把輪廓塗成綠色、周圍塗成白色。 這樣程式只會告訴你“站在那個位置時，史萊姆區塊剛好排成這個形狀”的地方。 如果只想找“孤立的一個史萊姆區塊”，那就中間塗一個綠色、緊挨著的八個格子塗成白色即可。

另外還有兩點小提示：行列數可以調整（1～64），數量就是圖案的格子數； 全部塗成灰色等於沒有條件，這時可以用「密度模式」去找“史萊姆區塊扎堆的地方”。 圖案編輯好之後記得點確定，主介面會顯示當前的圖案大小。

【四種模式怎麼選】

  • 精確模式（結果 100% 完整，推薦日常使用）：老老實實把範圍內每一個位置都算一遍， 不會漏掉任何一個符合條件的結果。範圍不大時速度也夠快，日常就用它。
  • 分層模式（快一些，但可能漏掉極少數情況）：先用粗略的條件快速篩掉大片不可能的區域， 只對“有希望”的地方細算，所以更快。絕大多數情況下結果和精確模式一致， 但在少數邊界情況下可能漏掉極個別的結果。追求速度、又不想等太久時可以選它。
  • 快速估算模式（非常快，但結果只是估計值）：只抽查一小部分位置來推算整體分佈， 速度非常快，但結果只是估計值、不是精確答案，可能漏掉真正的好位置。 適合“先大概看看這片區域值不值得搜”，不要用它來定最終座標。
  • 保守模式（最慢但最可靠，用於驗證）：不做任何取巧，一格一格從頭查到尾， 速度最慢但最穩。當你想確認某個結果到底對不對時，用它複核一遍最放心。

拿不定主意時：先用精確模式；嫌慢就換分層模式；只想快速看一眼就換快速估算模式； 需要“拍板確認”就換保守模式。切換模式後，結果區頂部會標出當前用的是哪種模式， 非精確的模式還會額外顯示一條提醒，看到提醒就知道結果不能當成百分之百完整。

【群系地圖 ≠ 地形圖】

群系地圖畫的是「這裡是什麼生物群系」（沙漠 / 平原 / 沼澤……），它決定史萊姆能不能刷、 火把要不要插、沼澤小屋在哪；地形圖畫的是「這裡高不高、是山還是海」，那是另一套噪聲。 本工具的地圖只做群系上色，不畫地形高度，也不畫結構（村莊/要塞）位置。

基岩版：1.18 以後兩版都用同一套「多噪聲生物群系引數」，所以同一個 64 位種子下 群系分佈高度接近；本工具按社群通行做法，用 Java 生成器跑同一份種子來近似基岩版群系， 地圖上會標註「基岩版≈Java 同種子」。兩版並非逐畫素一致（噪聲實現細節不同）， 如果你要對座標做嚴格規劃，建議以遊戲內 /seed + 實地確認的結果為準。

【GPU 加速是什麼】

如果你的電腦有獨立顯示卡，開啟 GPU 可以讓顯示卡一起參與大範圍搜尋。GPU 判定已經穩定， 結果與 CPU 逐位一致（不是「近似」）。

預設是關閉的：顯示卡不一定比 CPU 快——如果你的 CPU 很強、顯示卡一般，純 CPU 反而更快也更省電。 想用的話勾選「啟用 GPU 加速（預設關閉）」，也可以在「設定 → 效能」裡把它設為預設啟用。 勾選後程式會先檢測顯示卡能不能用：能用就交給顯示卡一起算；不能用或驅動不合適， 程式會自動改用 CPU 繼續算，不會彈錯誤窗、也不會崩潰。

參考資料（本專案在 AMD RX 6600 + Ryzen 5 5600 上的實測）：

  • Java 版：1 億區塊，GPU 約 7 ms，CPU 12 執行緒約 11 ms；
  • 基岩版：1600 萬區塊，GPU 約 10 ms，CPU 12 執行緒約 50 ms。

怕影響別的程式？「設定 → 效能」裡有「GPU 佔用率上限」：設成 50% 就是算一半、歇一半， 邊玩遊戲邊跑也不至於把顯示卡佔滿。第一次啟用時程式會自動實測本機 CPU 與 GPU 的吞吐率， 並在狀態裡直接告訴你「GPU 是本機 CPU 的幾倍」，按這個數字決定要不要長期開著即可。

【結果怎麼用】

每個結果旁邊有「複製命令」按鈕，點選後貼上到遊戲聊天框，就能直接傳送到那個位置。

複製到的是遊戲裡的一條 /tp 命令（形如 /tp @s 1234 64 -567）， 它會把你傳送到目標區塊的中心位置；如果只想看座標，直接讀卡片上的數字也一樣。 需要提醒的是：卡片上寫的是區塊座標，不是方塊座標， 而一個區塊有 16×16 格，所以命令裡的數字已經是幫你換算好的實際傳送位置， 不需要你自己再乘 16。傳送過去之後，往下挖到史萊姆能刷的層高（Java 版大致在 Y=40 以下）， 就可以動手建史萊姆農場了。

如果結果很多，卡片是按距離由近到遠排的，先挑最上面幾個近的去就行。

【為什麼基岩版比 Java 版慢】

兩個版本的判定演算法不一樣，速度差得比較遠，這裡說清楚，方便你決定怎麼設定：

  • Java 版用的是簡化的隨機數演算法（LCG，一次線性同餘遞推）， 單核實測約 5 億區塊/秒，所以範圍開大一點也很快。
  • 基岩版用的是完整的 Mersenne Twister：每個區塊都要先跑 624 步初始化再 twist， 單核只有約 3600 萬區塊/秒（比 Java 版慢十幾倍）。

所以給基岩版玩家的兩條建議：

  • 建議開啟 GPU 加速：基岩版掃描正是 GPU 擅長的批次計算，收益比 Java 版明顯得多 （程式會用實測基準告訴你這臺機器在多大範圍以上開 GPU 更划算）。
  • 建議開啟快取：第一次搜尋基岩版區域後結果會存到磁碟，之後再搜同一片區域幾乎秒出。

Java 版則相反：單核就已經很快，範圍不大時用 CPU 反而更快（GPU 的固定開銷佔比重）， 程式的狀態列會提示「建議關閉 GPU 加速」。

【常見問題】

問：搜尋結果很多怎麼辦？
答：設定「目標數量」，只顯示最近的 N 個。也就是說程式會從離你最近的位置開始數， 數夠 N 個就不再顯示了；想找更遠的，把 N 調大或者換更大的搜尋範圍即可。

問：搜尋很慢怎麼辦？
答：縮小搜尋範圍，或開啟 GPU 加速。範圍每擴大一倍，要算的位置大約多四倍， 所以先把範圍從「全域性」改回「附近」通常立竿見影； 大範圍又不想等，就按上面【GPU 加速是什麼】的說明把 GPU 開啟。

問：程式閃退怎麼辦？
答：點選「關於/聯絡我們」反饋（並附上 logs 目錄裡的日誌）。程式執行時會在 logs 目錄裡 記錄日誌檔案，把閃退前的那份日誌連同“你當時點了什麼、填了什麼”一起發過來，能極大加快定位速度。

問：為什麼一個史萊姆區塊都找不到？
答：先看這三件事：一是範圍是不是太小（換「區域性」或「全域性」再試一次）； 二是版本有沒有選錯（Java 版和基岩版的結果完全不同）；三是圖案是不是畫得太苛刻， 灰色格子太少會讓條件變得極難滿足，先把圖案清空或減少幾個綠色格子再搜一次。

問：我該信哪個模式的結果？
答：需要精確答案時用精確模式；快速估算模式的結果只是參考，不要拿它當最終座標； 分層模式在提示“無損”時和精確模式一致，出現提醒時則可能不完整； 心裡沒底就用保守模式複核一遍。

問：這個工具會改動我的遊戲存檔嗎？
答：不會。它只做計算，不讀取也不修改你的存檔檔案，複製的 /tp 命令也需要你自己 在遊戲裡貼上執行。使用前把遊戲存檔備份一份始終是好習慣。

還有別的疑問，歡迎透過「關於/聯絡我們」告訴我們，我們會把常見問題繼續補充到這裡。
