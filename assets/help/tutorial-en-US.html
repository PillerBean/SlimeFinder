Slime Chunk Finder - Tutorial

This page is for first-time users: you do not need to know any algorithm. Read it once and you will find slime chunks yourself. If you want to start right away, jump to "How to use".

What is this

A small tool that helps you find slime chunks - the places where slimes spawn - so you can build a slime farm.

  • Chunk: the game manages the world in 16x16 columns. The one near spawn is chunk (0, 0).
  • Slime chunk: slimes spawn below Y = 40 in these chunks, independent of light level. Roughly 1 chunk in 10 (about 10%) is a slime chunk.

Notes (Minecraft Wiki, "Slime"): slime chunks spawn slimes only below Y = 40; light does not matter; swamps also spawn slimes between Y = 51 and 69 at light 7 or less, but that is a different mechanic and this tool only handles slime chunks. Mushroom fields and the deep dark never spawn slimes (Bedrock also excludes rivers).

Why care? Dig a spawn room below Y = 40 inside a slime chunk and slimes keep dropping, giving you a steady supply of slime balls for redstone builds.

Key difference: Java slime chunks depend on the world seed plus chunk coordinates, so you must know the seed. Bedrock uses a different algorithm that does not depend on the seed - every world has the same layout - so Bedrock searches need no seed here.

How to use

1. Pick the edition (Java / Bedrock). Choosing the wrong one gives completely different results.

2. Enter the seed (Java only). Negative and very long numbers are fine. Use /seed in game (single player needs cheats enabled). Bedrock skips this step.

3. Pick a search range. The presets fill in the numbers: Near = +/-1000 chunks, Local = +/-5000, Global = +/-30000. Bigger ranges give more results and take longer; start with Near.

4. Pick a search mode. The default Exact mode returns 100% complete results; see "Choosing a mode" to trade completeness for speed.

5. Press Start and wait. The progress bar runs, the search happens in the background and the UI stays responsive. Results appear sorted by distance; click one to copy its coordinates.

Summary: edition - seed - range - mode - Start.

Drawing a pattern

The pattern editor is a grid where each cell is one chunk. Left click cycles grey to white to green:

  • Grey = do not care;
  • White = must NOT be a slime chunk;
  • Green = must be a slime chunk.

Paint only the cells you care about and leave the rest grey: fewer constraints mean faster searches and more results. Rows and columns are adjustable (1 to 64). An all-grey pattern means "no condition"; use Density mode to find clusters instead.

Choosing a mode

  • Exact (recommended): evaluates every position, never misses a match.
  • Layered: prunes large impossible areas first, so it is faster; in rare boundary cases it may miss a match.
  • Fast estimate: samples a small part and extrapolates; very fast but only an estimate.
  • Brute force: literal scan, slowest but easiest to trust for verification.

If unsure, use Exact. Non-exact modes show a warning above the results.

Biome map is not a terrain map

The biome map shows which biome a place is (desert / plains / swamp...) - that is what decides slime spawning, torch needs and swamp huts. A terrain map shows elevation and landform, which is a different noise layer. This tool only colors biomes; it does not draw terrain height or structures.

Bedrock: since 1.18 both editions share the same multi-noise biome parameters, so for one 64-bit seed the biome layout is very close. Following the common community approach, this tool runs the Java generator with the same seed to approximate Bedrock biomes and labels the map "Bedrock ~= Java same seed". The two editions are not pixel-identical (noise details differ), so verify important coordinates in game with /seed.

GPU acceleration

With a suitable GPU, enabling it lets the GPU join large scans. When enabled the program checks the device first: if it is unusable the search silently falls back to the CPU - no crash, no error dialog.

GPU is not always faster. The GPU status panel shows measured throughput for CPU and GPU on this machine; when in doubt leave it off and compare once.

Using the results

Each result has a copy button that gives a /tp command (for example /tp @s 1234 64 -567) already converted to block coordinates - no need to multiply by 16. Teleport there, dig below Y = 40 and build your farm. Results are sorted by distance, so start with the first few.

Why Bedrock is slower

  • Java uses a small LCG: about 500M chunks/s per core.
  • Bedrock uses a full Mersenne Twister (624-step init per chunk): about 36M chunks/s per core, more than ten times slower.

So for Bedrock: enable GPU acceleration (batch scanning suits GPUs) and enable the cache (the first scan is stored on disk; later scans of the same area are almost instant).

FAQ

Too many results? Set the target count N; only the N nearest are shown.

Too slow? Shrink the range (each doubling quadruples the work) or enable the GPU.

Crash? Report it via About / Contact us and attach the log from the logs folder.

No slime chunk at all? Check the range, the edition and the pattern (too few grey cells makes the condition almost impossible).

Which result should I trust? Exact for final answers, brute force to verify, fast estimate only for a rough idea.

Does it modify my world? No. It only computes; you paste the command yourself. Backing up your save is always a good habit.
